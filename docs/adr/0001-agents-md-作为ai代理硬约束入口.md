# ADR-0001：以 AGENTS.md 作为 AI 代理硬约束入口

- 状态：已接受（2026-10-12）
- 决策人：维护者（dennis）

## 背景

本项目以 vibe coding（AI 驱动开发）模式推进，不设人力与日历排期，实施顺序由技术闸门（G0–G6）驱动。质量保障方案（`docs/vibe-coding-质量保障方案.md`）的核心是：把"对不对"交给机器判定（契约 / 差分 / WPT / 快照 / 属性测试），人只审 ADR 与高风险面（unsafe、GC 桥、crypto、scheduler、PyO3 边界）。

约束若只写在方案文档里，只有人会读；必须让每个 AI 编码代理在会话开始时自动获得。

## 决定

1. 仓库根目录的 `AGENTS.md` 是对所有 AI 编码代理的强制约束入口，内容为质量方案的**执行摘要**（铁律十条 + 会话纪律 + 自检命令），细则以方案文档为准。
2. `AGENTS.md` 采用跨工具通用的约定文件名（大写），以便 Codex、Cursor 等识别 AGENTS.md 约定的工具自动读取；不识别的工具在会话开头手动注入。
3. 修改 `AGENTS.md` 需人工批准（列入 AI 不得自行修改的文件清单，见铁律第 7 条）。
4. 本 ADR 同时播种 `docs/adr/` 目录：此后一切架构决策先落 ADR 再写代码。

## 后果

- 正面：约束随仓库分发、随会话生效，不依赖人的自觉与记忆；修改有审计轨迹。
- 负面：AGENTS.md 需随项目演进维护（新增 crate、新增高风险路径时更新白名单与清单），维护成本由人工批准流程约束。
- 后续：G0 交付 compat-manifest 后，铁律第 8 条（兼容率单调性）由 CI 实际执行；workspace 建立后自检命令生效。
