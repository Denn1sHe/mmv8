## 0. 一句话问题

> 我们要用 Rust 写一个「浏览器环境模拟器」的内存核心。现在要拍板：**当一段 JS 值（对象/数组/函数）
> 要跨越「JS 引擎 ↔ 宿主」的边界存活一段时间时，宿主该用什么方式「记住它」，才能既让它存活、
> 又不会像我们实测过的那样造出一个永远回收不掉的内存环（泄漏）？**

## 2. 需要拍板的问题

- **主问题**：`JsHandle`（宿主侧代表一个 JS 值的轻量令牌）应该怎样把它指向的 V8 值存下来、
  何时释放、以及宿主怎样表达「我要这个值活着」？
- **子问题**：
  1. 句柄表的每个「槽位」应该存**强引用**（让 JS 值不会被回收）还是**弱引用**（不阻止回收）？
  2. 「宿主需要 JS 值存活」这件事，应该**隐式**由持有句柄表达，还是必须**显式**申请一个「存活租借」？
  3. 一句柄在释放后被复用，旧句柄应该报错还是静默指向新值？（复用防呆）
  4. 这样设计能否**逐条兑现** ADR-0009 的 C-1~C-4 四条硬约束？
  5. 涉及的 `unsafe`（绕过 Rust 内存安全检查的代码块）应该在哪、带什么不变量注释？

---

## 3. 备选方案（至少两个）

### 方案 A：**强引用槽表**（槽位直接存 V8 的 `Global` 强引用）

- **做法**：句柄表每个槽位保存一个 V8 强引用（`v8::Global`，可理解为「把 JS 值钉住、不让 GC 收走」）。
  只要槽位没释放，JS 值就活着。宿主「持有句柄」即「持有强引用」。
- **关键代码**（设计契约原文）：

  ```rust
  struct Slot { generation: u32, value: Option<v8::Global<v8::Value>> }
  pub struct HandleTable { slots: Vec<Slot>, free: Vec<u32> }

  impl HandleTable {
      /// 登记一个 V8 值：创建 Global（= 一次强引用/rooting）。
      pub fn alloc(&mut self, local: v8::Local<v8::Value>, realm: RealmId) -> JsHandle;
      pub fn resolve(&self, h: JsHandle) -> Result<&v8::Global<v8::Value>, JsError>;
      pub fn free(&mut self, h: JsHandle) -> Result<(), JsError>; // drop Global, generation += 1
  }
  ```

- **优点**：实现最简单；`eval` 返回值能安然交给 Python 以后再传回；语义直观（句柄在 ⇒ 值在）。
- **缺点与风险**：**「持有句柄」就等于「持有 GC 根」**——这正与 ADR-0009 的 C-1
  「`JsHandle` **不是** GC 根」的**字面**冲突。若有人把句柄存进 DOM 侧（C-2 禁止），
  重演 ADR-0007 的泄漏。
- **长期影响**：简单；但「句柄即根」的直觉会被误用，安全依赖纪律而非类型。
- **工作量**：小。

### 方案 B：**弱引用槽表 + 显式租借**（槽位存弱引用；存活必须显式申请）

- **做法**：槽位存**弱引用**（不阻止 GC）；句柄本身**不保证**值存活。宿主若要值跨调用存活，
  必须**显式**申请一个「存活租借」（`HandleLease`，一个 RAII 对象——离开作用域即自动释放）。
- **关键代码**（设计契约原文）：

  ```rust
  struct Slot { generation: u32, weak: v8::Weak<v8::Value> }   // 弱引用：不阻止 GC
  pub struct HandleTable { slots: Vec<Slot>, free: Vec<u32> }

  /// 显式强引用租借：只有持有一个 HandleLease 才保证值存活。
  /// 不实现 Clone / Copy —— 强引用环在类型上无法由「两个 lease 互相捕获」构造。
  pub struct HandleLease { /* 生命周期绑死 HandleTable */ }
  impl HandleLease { pub fn handle(&self) -> JsHandle; }
  impl Drop for HandleLease { fn drop(&mut self); }   // 离开作用域 → 释放
  ```

- **优点**：**C-1 字面成立**（句柄真的不是根）；「存活」这件事在代码里**看得见**（一个 lease 变量）；
  强引用环（C-4）在**类型层面**难以构造；DOM 侧用弱句柄（C-2）天然不泄漏。
- **缺点与风险**：`v8::Weak` 有**触发时机不确定**的特性（V8 文档明说弱回调「不保证何时、甚至是否被调用」），
  宿主需在「值可能已被回收」时优雅报错（用一个 `is_empty()` 检查）。
  `eval` 返回值若不在同一调用内用完，必须**先 root**，否则可能已被回收 —— 调用点稍繁琐。
- **长期影响**：更贴近 ADR-0007「只向上、弱引用」的结论；把「存活」变成**显式契约**，可审计。
- **工作量**：中。

### 方案 C：**混合**（控制面用强引用表，DOM 面用弱句柄）

- **做法**：Python SDK 的 `eval` 返回值放进一张**强引用**表（保证 Python 侧传回时值还在）；
  DOM 侧监听器槽用**弱句柄**（C-2）；`node_map` 用弱句柄 + 需要时 root。
- **优点**：两边各取所长；Python 用法直观。
- **缺点与风险**：**两套机制**，两套生命周期，理解与测试成本翻倍；
  「哪张表算根」变成需要记住的约定 —— 正是 ADR-0009 想避免的「靠纪律」。
- **工作量**：中偏大。

## 4. 证据（原文粘贴）

**证据 1 —— ADR-0009 决策 5，C-1 原文**：

> | **C-1** | **`JsHandle` 不是 GC 根。** 它的实现只能是 `engine-v8` 内部 `slot table` 的下标（一个 `Vec` 的下标），**不得**是 `v8::Global` 的包装 |

**证据 2 —— ADR-0007 实测原文（泄漏已发生）**：

```
=== EXP3 真循环：DOM → Global(闭包) → 闭包捕获 DOM ===
  WeakRef 判定：exp3 存活 = true（**true = 被跨语言环保活，即泄漏**）
CYCLE_LEAK=true
```

> 根因原文（ADR-0007）：「cppgc 堆与 V8 堆是**两个独立堆**，V8 GC 只认识自己的根，
> 而 `v8::Global` 正是这样一个根。」

**证据 3 —— ADR-0007 的 API 约束原文（写句柄表会踩）**：

> | `v8::String::new` 返回 `Option` | 直接 `.into()` 变不出 `Local<Value>`，需先 `.unwrap()` |
> | 宿主回调不返回 `Result` | 直接设返回值参数 `rv` |
> | v8 scope 类型多生命周期参数 | 抽成具名函数会 E0106；用宏在同作用域展开 |

**证据 4 —— 现有仓库事实（已核实）**：

```

```

## 5. 本仓库的既定约束（外部/内部评审必须在此边界内给建议）

- **铁律 4**（`AGENTS.md:21`）原文：「**unsafe 全仓禁止**（workspace lints 强制）。仅白名单 crate
  （`engine-v8` 及显式声明的 FFI 薄桥）例外，且每个 unsafe 块必须带 `// SAFETY:` 不变量注释。」
- **铁律 5**（`AGENTS.md:22`）原文：「**V8 / rusty_v8 类型不得越出 `engine-v8` crate**。」
- **铁律 6**（`AGENTS.md:23-27`）把「`engine-v8` 中的 unsafe 块与 GC 桥」列为**高风险路径**，
  改动须走决策上报获批。
- **ADR-0009 决策 5 C-1~C-4**（硬约束，原文摘要）：C-1 句柄非 GC 根；C-2 `web-dom/web-events`
  类型面不得出现 `JsHandle`；C-3 `NodeId↔JsHandle` 表归 `engine-v8`；C-4 禁止强引用环
  （跨堆追踪本轮不做）。
- **守卫脚本规则 3**（`check-unsafe-whitelist.sh`）：`SAFETY:` 注释必须在 unsafe 行**前 2 行内**。
- **ADR-0007 遗留**：真跨堆追踪（ephemeron）需 unsafe 桥接，**本轮不做**。

## 6. 本代理的推荐（**仅供参考，等待内部辩论**）

- **推荐方案 B（弱引用槽表 + 显式租借）**，理由：
  1. 它是**唯一让 C-1 字面成立**的方案（「句柄不是根」在代码里是真的）；
  2. 它把「存活」从**隐含直觉**变成**显式契约**（一个 lease 变量），与 ADR-0007
     「单向/弱引用」的方向一致；
  3. 强引用环（C-4）在类型上难构造（`HandleLease` 不 `Clone`/不 `Copy`），
     把「不泄漏」从纪律升级为**类型约束**；
  4. 代价（`v8::Weak` 时机不定）可控——用一个 `is_empty()` 检查 + 明确的错误类型即可。
- **我不确定的点（希望重点看）**：
  1. `v8` 152.2.0 的 `v8::Weak<Value>` 具体 API 形态与「回收后读取」的确切行为，需工程师先做
     **最小实测**（类似 T2.1 的 `WeakRef` 判定法）；
  2. 方案 B 下，Python 侧 `eval` 返回的句柄「活多久」是否需要一个默认租借策略，
     否则用户拿到句柄后可能已被回收 —— 是否会伤害可用性；
  3. 方案 A 的「简单」是否值得用「C-1 字面冲突」来换。
