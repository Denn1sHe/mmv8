## 决策 1（D-02）：仓库许可证 = `Apache-2.0 OR MIT` 双许可

**选项**

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A. `Apache-2.0 OR MIT`（**选定**） | `Cargo.toml` 写 `license = "MIT OR Apache-2.0"`；仓库根放 `LICENSE-MIT` + `LICENSE-APACHE` | Rust 生态事实标准；与 MPL-2.0 / BSD-3 依赖均可链接；使用者可任选 | 无实质风险 |
| B. `MPL-2.0` | 与 Stylo 系一致 | 与 MPL 依赖同源，豁免问题最少 | MPL 是文件级 copyleft，会限制把本仓库代码并入闭源产品的意愿（本项目面向风控场景，使用者多为闭源集成） |
| C. 暂不声明 | 维持现状 | 无需动作 | `cargo deny` 的 licenses 检查对 workspace 自身成员会失去依据；wheel 元数据缺 license 字段，分发不合规 |

**选定 A 的理由**：本仓库 `publish = false`、只分发 Python wheel（技术方案 §19）。
依赖侧已核实包含 `MPL-2.0`（`stylo_dom 0.20.0`）、`BSD-3-Clause`（V8 / Skia）、
`Apache-2.0 OR MIT`（html5ever / parley 等）；这些许可均允许被 Apache-2.0/MIT 项目
链接与再分发，`deny.toml` 的 `[licenses].allow` 白名单已经覆盖（见该文件第 35–50 行）。
**MPL-2.0 合规要求**：不得修改 MPL 覆盖的第三方源码文件；若必须打补丁，改动须公开。
本项目不对 Stylo/Blitz 源码做本地 fork，故仅为"使用"。

**备注**：如果维护者日后倾向 copyleft，改选 B 只需替换 `Cargo.toml` 的 `license` 字段与
两份 LICENSE 文件，无代码影响。

## 决策 2（D-03）：MSRV 策略与 CI 工具链矩阵

**已核实的事实**

- `edition = "2024"` 要求 `rustc ≥ 1.85`；当前 `Cargo.toml` 的 `rust-version = "1.85"` 是意向值。
- 本地开发机 `rustc 1.92.0`；远程验证机 `rustc 1.99.0`。
- `v8` crate（crate 名，仓库名 rusty_v8）最新版 `152.2.0` 的 registry 元数据里
  **没有 `rust_version` 字段**（已用 `curl https://rsproxy.cn/index/v8/v8` 核实），
  因此无法从元数据确定它真正要求的最低编译器版本。

**决策**：MSRV 采用"**声明即验证**"原则，分两步走，不阻塞 T1/T2：

1. **现在**：`rust-version` 暂保持 `1.85`，但**在 CI 中不把 1.85 作为通过性门槛**——
   改为固定两档矩阵：`stable`（跟踪最新）与 `1.92.0`（本地开发基线）。
   这样避免"声明了 MSRV 但从未验证"的假绿（质量方案 §1 的原意是验证，而非声明）。
2. **G1 之前补齐**：引入 `cargo-msrv`（或 `cargo hack` 的 msrv 子命令）在 CI 中
   自动二分探测真实 MSRV，探测结果回写 `rust-version`，并把探测出的值加入矩阵。
   登记为 T0 遗留 TODO（见 TASKS.md），**不阻塞 T1/T2**。

**`cargo geiger`**：接入 CI，但**作为 `warnings` 级门禁**（输出 unsafe 统计），
不参与 `-D warnings`。理由：`cargo geiger` 会把依赖树里的 unsafe 也统计进来，
而 V8/Skia 等 C++ 绑定必然含 unsafe；把它当阻断门会让门禁永远红，失去信号价值。
它的作用是**趋势可见**：engine-v8 自身的 unsafe 块数量应保持个位数并逐块有 SAFETY 注释。

## 决策 3（D-04）：托管与 CODEOWNERS

**事实**：`CODEOWNERS` 现按 `@dennis` 占位（AI 起草时标注"待维护者批准"）。
`git init -b main` 已完成，**未做首次提交**。

**决策**：保持 `@dennis` 占位，但必须让"占位未核实"这件事**在文件里可见**——
已在 `CODEOWNERS` 头部标注；本 ADR 再次明确：

- 若仓库最终托管在 GitHub 且账号不是 `dennis`，则**所有保护规则会静默失效**
  （GitHub 对无法解析的 owner 不作提示，这是真实且危险的失效模式）。
- **首次提交与 PR 模板的落地仍待维护者提供**：① 托管地址（GitHub org/repo）；
  ② `git config user.name` / `user.email` 的实际提交身份。
  AI 不代填身份（会污染提交历史）。

2. **AGENTS.md「提交前自检」清单**：在 Rust 侧自检命令中**追加一行**
   `bash scripts/check-unsafe-whitelist.sh`。

**关于铁律 7 的例外声明**：铁律 7 禁止 AI 修改 `AGENTS.md` 自身。本次修改是
**维护者授权范围内的最小改动**——只追加一条自检命令，**不动铁律任何一条**。
若维护者不认可，回滚该行即可，无其它影响。
