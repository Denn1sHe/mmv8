## 问题

页面「等待网络」的接口语义 + 响应回填的线程/重入安全 + 新导航的作废语义 + G2 新增 PyO3 入口的重入纪律。
两评审均**同意方案 A（有界推进 + 入队回填 + epoch 作废 + 绕开 `PromiseResolver`）**，`WaitingIo` **逐字兑现** §6 docx:185；
但指出导航语义被高估、`res/rej` 表无归宿、PyO3 重入未覆盖、依赖环等。

## 决策

### 决策 1 —— 主形态：有界推进 + 入队回填 + epoch 作废 + `WaitingIo`

`run_until` **有界**（`max_tasks` + 墙钟）；队列空但仍有未完成 I/O/停泊任务 ⇒ 返回 `WaitingIo`（**不凭空完成**）。
`network.complete(id, resp)` **只入队**（`TaskSource::Network`），resolve 发生在下一次 `run_until` 跑到该任务时
（对齐 §6 docx:178「I/O 线程仅投递纯数据；页面线程创建 JS 值并 resolve」+ ADR-0014 决策 1）。

### 决策 2 —— 导航**重绑过程**定稿 + 具名登记偏差（B-4 / 施工图 U-9）

技术方案 §4 docx:147「新导航撤销旧文档任务……延迟返回的旧响应不能写入新页面」；docx:146「关闭与导航不能只清空全局变量」。
**单 Realm 下 epoch 只挡「任务落地」，旧文档的 JS 全局（`document`/DOM wrapper/pending Promise 的 resolve 闭包）
在同一 Context 内仍存活** ⇒ 施工图 §7 U-9 的「与 G1 同构、无碍」推论**被攻破**。定稿：

> **导航 = 原地重建文档/树/绑定**：`begin_navigation(url, snap)` 使 epoch+1、`readyState=Loading`、清 blockers，
> 并**重建全新 `NodeTree`**（生成新文档根；**generation 基线单调**，使 `NodeId` 跨导航**不别名**）+
> **清 `node_map`**（`unbind`/重建 `PageBinding`）+ **清 `ListenerRegistry`** + **清 `MutationBuffer`** +
> **重建 `ParserHost`**（ADR-0017 决策 7）。

- **可观察断言**：`stale_document_node_rejected`（旧文档 `NodeId` 在新文档被拒）。
- **具名登记偏差**：G2 **不新建 Context/Realm**，旧 JS 全局残留（Realm 级替换属 **G4**）；
  登记于 §8 + `capabilities`。
- `begin_navigation` 签名**扩展**为承担上述重建（不再只动 `url/readyState/blockers/epoch`）。

### 决策 3 —— `res/rej` 表归宿 + `complete` 语义 + 两条 resolve 路径（B-6）

- **归宿定稿**：`Rc<RefCell<FetchTable>>`，`FetchTable: HashMap<RequestId, PendingRequest{ resolve: HandleLease, reject: HandleLease }>`；
  由 **`PageShared` 持有**，`__iv8_fetch` 闭包**直接捕获**该 `Rc`（**P-1b 已定**：`NativeFn` 去 `+ Send`，**无侧通道**）。
  **`network` crate 保持零 `engine-v8` 依赖**（`HandleLease` 只出现在 `navigation` 类型面，合法）。
- **两条 resolve 路径**（写清 + 各一条测试）：
  1. **OfflineBundle 同步命中** ⇒ `__iv8_fetch` 内**就地 resolve**（`FetchOutcome::Ready`）；
  2. **host `complete`** ⇒ 入队 `Network` 任务 ⇒ `run_until` 内 resolve（`FetchOutcome::Pending`）。
- **`complete` 语义**（写死）：
  - pending 且 epoch 当前 ⇒ `Ok`（置 `Completed` + 入队 resolve 任务）；
  - **同一 `RequestId` 已完成再次 `complete` ⇒ 幂等 `Ok`（no-op）**；
  - **已 `abort` / epoch 过期 ⇒ `Err(NetworkError::Stale)`**（**不写入**，可判定）。
- `abort_epoch(epoch)` / `close()` 的 **lease drop 时机**：abort 即释放该请求 `res/rej` 的 `HandleLease`；close 排空全表。

### 决策 4 —— epoch 覆盖面扩展（timer/input）+ `TaskToken` 携带方式（B-断链）

§4 docx:147 明列「异步请求、**句柄、Worker 和日志条目**」均带 epoch。定稿：
- **`timer`/`input` 任务同挂代次**（不只 network）；
- **`TaskToken` 携带方式定稿**：`TaskToken` 仍是不透明 `u64`（scheduler 不依赖 navigation），
  但**导航相关任务的登记表**（`navigation` 侧）把 `TaskToken → NavigationEpoch` 关联；
  任务落地前**统一 epoch 校验**（`controller.is_current(epoch)`），旧代次一律丢弃。

### 决策 5 —— PyO3 重入覆盖扩展 + 所有权定死（A-B7；触发 ADR-0014 修正注记）

ADR-0014 决策 3「`in_callback` 必须 RAII 且**覆盖全部重入入口**」。G2 新增 `run_until`/`page.load`/
`network.complete`/`input.dispatch` 一律**沿用 G1 形态**（`sdk-python/src/lib.rs:122` 六处）`try_borrow_mut()`
→ 投影为 `ReentrantEval`（**可判定错误，非 `RefCell` panic**；铁律 10）。
- **`PyPage`/`PyNetwork`/`PyInput` 所有权定死**：各持 **`Rc<RefCell<BrowsingContext>>`**（**不**用
  `Py<PyContext>` 反向引用，避免 Python 级环 + 借用交织）。`PyContext` 亦持同一 `Rc`，各自 `RefCell` 包一层。
- **专测** `py_control_reentry_is_error`；**S14 首步验收项**。
- **ADR-0014 追加修正注记**：把「覆盖全部重入入口」限定显式纳入 G2 的 `PyPage/PyNetwork/PyInput`。

### 决策 6 —— URL/origin 规范化修正（A）

`Origin::from(url)` 规范化：**query/fragment 剥离**、**default-port 折叠**（`https://a:443` ≡ `https://a`）、
**scheme/host 小写**；测试含**端口断言**。落 §3.4 `origin_computed_from_url`。

### 登记（不阻断）
- `network.complete` **批量接口**（§16 docx:412「大量请求采用批量消息接口」）：G2 单条 `complete(id,resp)` 与批量建议
  **并存不冲突**，**批量留 G6**（在线传输）——登记，避免被读成遗漏。

## 后果

### 正面
- 「旧响应不写新页面」由「任务落地校验」+「文档/树/绑定重建」**双重**保证；单 Realm 的旧全局残留**具名登记**（不假绿）。
- `res/rej` 表有归宿且 `network` 保持零 `engine-v8` 依赖；`complete` 语义（含重复/幂等/过期）**全部可判定**。
- G2 新增 PyO3 入口纳入重入纪律（与 G1 同一形态，无 panic 面）。

### 代价（如实登记）
- `begin_navigation` 扩权（承担重建）⇒ S10 工作量上升；`PageShared` 需新增 `fetch_table: Rc<RefCell<FetchTable>>`。
- `PyPage/PyNetwork/PyInput` 所有权形态改动 ⇒ S14 需同步 `PyContext`。

### 待实测登记
| # | 待实测项 | 落点 |
|---|---|---|
| T4 | 导航后旧 `NodeId` 被拒（`NodeId` 跨导航不别名） | S10（`stale_document_node_rejected`/`node_id_not_aliased_across_navigation`） |
| T5 | 两条 resolve 路径各自可达 | S13（`fetch_offline_hit_is_ready` / `network_complete_resolves_promise`） |
| T6 | PyO3 新入口重入报错而非 panic | S14（`py_control_reentry_is_error`） |

### 遗留（本 ADR 不做）
- 批量 `complete` 接口（G6）；Realm 级导航替换（G4）。
