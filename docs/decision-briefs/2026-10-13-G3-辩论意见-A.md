## ① 结论

> **有条件支持（Conditional Support）**——**方向同意，机制与判据不接受**。

- **同意的部分**：ADR-0011 的 `SWITCH_TO_STYLO` 结论**在今日证据下仍成立**：blitz-dom 0.3.0-beta.2 的
  Shadow 相关方法确为 `todo!()` / 恒 `None` 桩（已逐行复核，见 §附录 E），据此触发技术方案 §8 的替代路线
  是被授权的裁决；「直连 Stylo + Taffy + Parley」的**接口不变（C14）**、**不省依赖（C15）**两条纪律表述正确。
- **不接受的部分（阻断）**：
  1. **D1 的「核心价值主张」未被证据支持、且 P-4 判据打错了靶**：直连路线声称「自建 `Element` 可绕开
     blitz 的 `OpaqueElement` rehydrate 结构性限制」，但该限制的载体是一个**无 `self` 的关联函数**
     （`implicit_scope_for_sheet_in_shadow_root(host: OpaqueElement, sheet_index)`），我们自建同样只有 64-bit
     `OpaqueElement`、同样拿不到树引用；而 P-4 的判据（light 查询为空 + `::slotted` 命中）**根本不调用该函数**。
     ⇒ 设计既未证明、也未**测量**它宣称要绕开的东西（**B1**）。
  2. **S1 与 S6 次序自相矛盾**：P-4 需要影子根数据结构（`attach_shadow`/`NodeKind::ShadowRoot`），而那在 S6 才建，
     S1 却在 S6 之前（**B2**）。
  3. **P-5 / U-9 / R11(c) 的「与 Chromium 逐属性对齐」判据在仓内不可执行**：唯一后端是 `NullDifferentialBackend`
     （`real=False`，不接触浏览器）（**B3**）。
  4. **D2 的备选 B 版本数字不可复核，且 D3 的 MSRV 论据失实**（**B4**）。
  5. **施工图有算式级自相矛盾**（`clientWidth==94` vs §3.4 自身公式，正确值 96）（**B5**）。

> **整批不通过**（施工图 §6 R11 意义上的「不过」），须先修 **B1~B7** 再落 ADR-0020~0023。

## ② 逐决策点评（D1~D4 + 核心设计点）

### D1 —「立即启动直连 Stylo + Taffy + Parley」（brief `2026-10-13-G3-stylo-direct.md`）

| 项 | 评审 |
|---|---|
| 备选是否 ≥2 且真实 | **不完全**。A/B/C 三案，但 **C（暂不做 Shadow）是稻草人**：brief 自述「违反 §18」「不满足闸门」（brief:92-95）。**缺**一个真实备选：**blitz + 在 stylo 侧修形 `opaque()`**（详见 B8）。 |
| 证据可否复核 | A/B/D 可复核（blitz 行号已逐行核对，见附录 E）；**B（ADR-0011「结构性限制」引文）** 原文存在，但**定性过强**（B8）。 |
| 推荐是否锚定/掩盖更优解 | **有锚定**：brief §6 把 A 与 S1 探针捆绑，读起来像「A 已被探针保护」，但**该探针（P-4）不检验 A 的核心前提**（B1）。 |
| 判据是否够硬 | **不够**。P-4 判据（brief:174 / design:689）与 blitz 真正堵点错位（B1）。 |

**核心设计点（可辩三口径）点评**：
- **几何口径（D5）**：`offsetWidth`=border-box 取整 / `clientWidth`=padding-box / `gBCR`=视口坐标 / `getComputedStyle`=stylo 计算值——
  方向与 CSSOM 一致，**但 §3.2 的 `clientWidth==94` 算错**（应 96，B5）。
- **Shadow 边界（D6）**：把「事件 retargeting/`composedPath`/`slotchange`」推 G4 可接受；**但**「G3 只做作用域隔离」
  这一句掩盖了 B1——作用域隔离依赖 `implicit_scope_for_sheet_in_shadow_root`，恰恰是被 blitz 标为堵点的那一步。
- **字体确定性（D7）**：内嵌字体方向正确；但断言过弱（B10）。

### D2 — 锁版与补丁策略（brief `2026-10-13-G3-blitz-lock.md`）

- **版本组合与 `Cargo.lock` 实况：完全一致**（已逐条核对，见附录 E 表）。这一条**我不反驳**。
- **「反对跟随最新（0.22 会双版本并存）」——机制成立，但**证据不可复核**：
  - 机制：`stylo_taffy 0.3.0-beta.2` 的 `[dependencies.style] version = "0.20.0"`（= `^0.20.0` = `>=0.20,<0.21`）。
    写 `stylo="0.22"` ⇒ 与 `^0.20` 不交集 ⇒ 双版本并存。**属实**。
  - 但「stylo 最新 0.22」「parley 最新 0.12.0 MSRV 1.88」**本地 registry 无此版本**（`stylo-*` 仅 0.20.0；
    `parley-*` 仅 0.11.1/0.2.0），且 AGENTS.md 禁联网 ⇒ **该两处事实不可复核**（B4）。
- **结论（锁版方案 A + 保 C 补丁通道）**：**同意**；但 §2.4 的「同源证据」链条弱于其表述（B4(i)）。

### D3 — 工具链钉版 K-14（brief `2026-10-13-G3-toolchain-pin.md`）

- 方案 A（钉 `1.92.0`，CI 矩阵收敛须维护者批准）**合理**，与两次单端红（brief 证据 E/F）的因果判断一致。
- **但论据失实**：brief:81 说「`parley` 最新 `0.12.0` 的 MSRV 是 **1.88**……与本仓 `rust-version="1.85"` 声明冲突更甚」——
  **`parley 0.11.1`（被钉的那一版）自身就是 `rust-version = "1.88"`**（`parley-0.11.1/Cargo.toml:14`）。
  即 MSRV 冲突**已经存在**，不是 0.12 引入的；且 `stylo_taffy 0.3.0-beta.2` 要求 `rust-version = "1.89.0"` + `edition = "2024"`。
  ⇒ 钉 1.92 解决了「工具链」，却**没有解决**「workspace `rust-version = "1.85"` 声明的既存违背」（B4）。
- 建议：D3 必须同时给出对 `rust-version="1.85"`（root `Cargo.toml`）的处置（改声明 / 明示「声明即验证」不覆盖新依赖）。

### D4 — 残余排程（brief `2026-10-13-G3-residual-scheduling.md`）

- **推荐自相矛盾**：brief:130 推荐「方案 B（timer 事件循环 + 模块 watchdog 归 G3）」，但**施工图 §3.3 的四条失效测试
  全部是同步脚本 + 显式 `resolve`**（design:533-535），即设计**自身已经证明** U-1/U-4 成立（失效测试可同步完成）
  ⇒ 按 brief §2 子问题 1 的判据，应落到**方案 A**。
- **timer 触铁律 6**（scheduler 高风险路径）⇒ 若确要做，**必须单列 ADR**（brief 已注明）。
- **模块 watchdog（U-12）**：是**安全缺口**，与布局因果上可解耦；建议**单列 P0**，不要塞进「视 D4 裁决」的 P1/P2 里被顺延。
- 建议：D4 结论改为 **方案 A（四项全推 G4）+ 模块 watchdog 单列 P0 安全项**。
