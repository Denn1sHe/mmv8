## 问题

P-1 实测：`style::dom::TElement` 有 **5 个必需 `unsafe fn`**（`stylo-0.20.0/dom.rs:648/675/680/739/744`，
无默认），而全仓 `unsafe_code = "forbid"`（`Cargo.toml:67`，不可被 `#[allow]` 覆盖）⇒ 承载 `TElement`
实现的 crate **不可能零 unsafe**。需拍板白名单**落点形态**：谁承载 impl、豁免粒度、如何用**机器门禁**
保证「unsafe 面不蔓延」。

## 决策

### 决策 1 —— **`layout-backend` 本地 lints（`forbid → deny`，engine-v8 同款）**

`crates/layout-backend/Cargo.toml`：`[lints] workspace = true` → **本地声明**，等价 lint 集合，
仅 `unsafe_code` 由 `forbid` 放宽为 `deny`（`missing_docs`/`clippy` 与 workspace 逐项相同）。
理由：`unsafe_code` 是 **crate 级** lint，`forbid` 不可被 `#[allow]` 覆盖 ⇒ 承载 impl 的 crate 必降 `deny`。

### 决策 2 —— **E′：守卫白名单「数据行」追加尾斜杠目录**（零 bash 逻辑改动）

```diff
 WHITELIST=(
   "crates/engine-v8/"
   "poc/"
+  "crates/layout-backend/src/stylo_host/"
 )
```

- 尾斜杠目录条目 ⇒ `[ -d "$prefix" ]`=true ⇒ **规则 3/4 自然生效**（SAFETY/开口检查覆盖该目录）；
  `grep -RInE ... <目录>` 自带 `文件:行:` 前缀 ⇒ **不需要 `-H`**；
- **非桥文件仍被规则 1 文本拦**（`layout-backend` 其余 `src/**` 不在白名单）；
- **规则 5 对该目录失效**（白名单条目使 `is_whitelisted` 豁免）⇒ 由 **R 的门禁 d** 补位（见决策 3）。

**如实记录 B 的反对（裁决 §六·1）**：B 论证 **E′ 的文本最小化净增益≈0**——(i) 编译器 `deny` **已强制逐项 `#[allow]`**
（删一个即编译红）；(ii) **宏生成的 `unsafe` 编译器照样命中**（实测 `forbid` + `macro_rules!` ⇒ 报
「declaration of an unsafe function … in this macro invocation」）⇒「文本检不出」并非真缺口；
(iii) F（A + 独立 Rust 门禁）**用独立门禁用同样的窄化、且不必改执行器**。
**保留 E′（子目录条目）的残余理由（裁决保留）**：**tamper 场景**——当**非受保护的 Rust 门禁与违规改动同 PR 被削弱**时，
E′ 下**受保护的 bash 规则 1**（`CODEOWNERS` 保护、需批准）**仍拦非桥文件**；而 F 的 crate 级条目则**全程依赖
可被同 PR 修改的 Rust 断言**。⇒ 维持子目录条目（**代价≈0**；未来新增第二目录 = 再加一条白名单项，本就属铁律 6 审批范围）。

### 决策 3 —— **R：新增 Rust 门禁断言 a/b/c/d**（机器保证，替代 bash 计数规则）

扩 `crates/runner/tests/workspace_policy.rs`（或同文件新断言）：
- **a**：`src/stylo_host/**` 的 `unsafe fn` **名集合恰 == 上游 5 名**，且**计数 == 5**；
- **b**：`layout-backend/src/**` 除 5 具名方法（含其体内 **≤ N** 处 `unsafe` 块）外，**不得出现任何其他
  `unsafe` 文本**（`unsafe {` / `unsafe impl` / `unsafe trait` / 其他 `unsafe fn`）；
  **阈值 P-1b 已回填：`N = 0`（终值，不上调）**（实测 **signatures:5 / bodies:0 / 腔体:0**，commit `407c0aa`）
  ⇒ **信封口径 = 「5 声明 + 0 腔体」**。
  **依据（零腔体出路已证）**：`ElementDataWrapper::borrow/borrow_mut` 为**安全 `pub fn`**
  （`stylo-0.20.0/data.rs:332/344`；`pub mod data` = `stylo-0.20.0/lib.rs:76`）、
  `ElementDataMut: DerefMut<Target = ElementData>`（`data.rs:371`）、`ElementData: Default`（`data.rs:287`）
  ⇒ 急切持有 wrapper 后，`ensure_data = self.w.borrow_mut()`、`clear_data = *self.w.borrow_mut() = ElementData::default()`
  **全是安全操作**（代价 = 逐元素急切分配；G3 本就逐元素存样式，可接受）；
- **c**：`layout-backend` lint 副本**逐项 == workspace**（防漂移，engine-v8 同款）；
- **d**：`layout-backend` 文本**无 `v8::` / `extern crate v8`**（**规则 5 的等效补位**——白名单条目使规则 5 对该目录失效）。

### 决策 4 —— **`workspace_policy.rs` 既有断言修正**（两评独立互证的必做项）

`WHITELISTED_CRATE`（单值）→ `WHITELISTED_CRATES`（集合）；`only_whitelisted_crate_opts_out_of_workspace_lints`
的豁免分支覆盖 `layout-backend`；`engine_v8_lint_block_...` 泛化为「任一台白名单 crate lint 副本 == workspace（除 unsafe_code）」。
（B 案原触的 `workspace_members_equal_scaffold_roster` **不在本裁决范围**——本 ADR 不新增成员。）

### 决策 5 —— **反向注入四态（强制）**

① 删一个 `#[allow]` ⇒ **编译红**；② 非桥文件加 `unsafe {}` ⇒ **门禁 b 红**；③ 恢复 ⇒ **绿**；④ 清理 ⇒ **绿**。

### 决策 6 —— `cargo geiger` 本轮排入 + 留档基线

`cargo geiger` 运行并**留档 unsafe 计数基线**（文本盲区兜底 + 趋势；对齐 ADR-0002 既有 geiger 机制）。

### 决策 7 —— **CI 执行性核验**

核实 `ci.yml` **实际执行**守卫脚本与 runner 测试。（**架构师已核，见 §9 证据**：lint job 执行
`bash scripts/check-unsafe-whitelist.sh`；test job `cargo test --workspace` 覆盖 `crates/runner/tests/`。）

### 决策 8 —— 上游升级回收条款

stylo 系升级（按 ADR-0021 流程）时**强制复核 5 名集合与 SAFETY 依据**；集合或语义变更须**重落 ADR**。

### 决策 9 —— **翻盘条件（登记）**（裁决 §六·4）

> **S6 定形若证「unsafe 面 > 2 处且跨多文件」** ⇒ 按「**unsafe 面 × 文件数**」**重评薄桥 crate（B）**。
> 依据：B 是**唯一保持编译器级 `forbid`** 的形态（连 `#[allow]` 都报 E0453）；其价值**随该乘积增长**；
> **本信封下（5 声明 + 0 腔体、集中单目录）不划算**，故本轮否。
> 上游若把 `unsafe fn` 改安全签名或提供安全 `clear` ⇒ **主动回收**本豁免（同登记）。

## 被否决方案（记录）

| 方案 | 否决理由 |
|---|---|
| **②**（deny + allow，无白名单条目） | 守卫需新增「例外 crate + 仅允许带 allow 的项」分支（无先例、复杂度最高）；文本层 `#[allow]`↔`unsafe fn` 配对极脆 |
| **B（薄桥 crate）** | 孤儿规则（E0117）迫使桥内自建 `NodeRef`/newtype ⇒ 须承担全 `TElement/TNode/selectors::Element` 面 ⇒「极薄」**不可达**；且重开 ADR-0009 冻结名单（19→20 + §16 解冻）。**留维护者覆写口**（若最重「编译器级 `forbid`」） |
| **E 草案（按文件）** | 前缀匹配**误放行** `.rs_evil.rs`；单文件 `-R` 无文件名前缀 ⇒ 需加 `-H`；`[ -d ]` 使文件条目**跳过规则 3/4** ⇒ 须改 bash 逻辑（与「不动执行器」冲突）；诉求被 E′ 覆盖 |
| **A（整 crate 条目）** | 被 E′ **完全支配**（同 `[lints]` 改动、同不改脚本；A 让**整个大 crate** 豁免、无补偿收益） |
| **不实现 `TElement`** | 级联不可行 ⇒ 与 ADR-0011 冲突 |

## 后果

### 正面
- 白名单为「engine-v8 + 显式声明的 stylo FFI 薄桥（**目录**）」两支；unsafe 面**机器可证**（a/b/c/d）；
- **零 bash 执行器改动**（守卫只是多一行数据）；桥以**目录模块**（`stylo_host/`）承载，「薄桥」语义落地；
- 不新增 workspace 成员（不触 ADR-0009）。

### 代价（如实登记）
- `layout-backend` crate 级 `deny` ⇒ 编译器不再对**该 crate**「未 `#[allow]` 的 unsafe」之外的情形兜底
  （但门禁 b 补文本面）；白名单由「唯一」变两支。
- 守卫**规则 5** 对桥目录失效 ⇒ 依赖 **门禁 d** 补位（若 d 未落，则 `v8::` 可在桥目录逃逸）。

## 对 ADR-0002 的更正注记

2. 「白名单必须**逐块**开口、禁 crate/mod 级开口」**不变**；新增 Rust 门禁 a/b/c/d 作为**机器执行**。

## 对 ADR-0020 的更正注记
- 决策 2 的「**零 unsafe 为准**」**落点已定**（本 ADR-0024）：opaque 机制零 unsafe（已验证）；

### 7.3 **新增门禁断言 a/b/c/d**（草案，置于 `workspace_policy.rs`）

```rust
// ==== ADR-0024 R 门禁：stylo FFI 薄桥 unsafe 面 ====

/// 上游 `TElement` 的 5 个必需 `unsafe fn` 名（stylo-0.20.0/dom.rs:648/675/680/739/744）。
const TELEMENT_UNSAFE_FNS: [&str; 5] = [
    "set_handled_snapshot",
    "set_dirty_descendants",
    "unset_dirty_descendants",
    "ensure_data",
    "clear_data",
];

/// 桥内**体内** `unsafe` 块允许上限（**P-1b 终值 0**，commit 407c0aa：signatures:5 / bodies:0 / 腔体:0）。
const STYLO_HOST_MAX_BODY_UNSAFE_BLOCKS: usize = 0; // P-1b 定格；不再上调

/// 截行内注释并去首尾空白（复刻守卫脚本 code_part 语义）。
fn code_part(line: &str) -> &str {
    line.split("//").next().unwrap_or("").trim()
}

/// 递归收集某目录下 .rs（复用既有 collect_rs_files）。
fn rs_files_in(dir: &std::path::Path) -> Vec<std::path::PathBuf> {
    let mut v = Vec::new();
    collect_rs_files(dir, &mut v);
    v
}

// (a) stylo_host/** 的 unsafe fn 名集合恰 == 5 名，计数 == 5
#[test]
fn stylo_host_unsafe_fns_are_exactly_the_five() {
    let root = workspace_root();
    let mut names: Vec<String> = Vec::new();
    for f in rs_files_in(&root.join("crates/layout-backend/src/stylo_host")) {
        for line in std::fs::read_to_string(&f).unwrap_or_default().lines() {
            let code = code_part(line);
            if let Some(rest) = code.strip_prefix("unsafe fn ")
                .or_else(|| code.strip_prefix("pub unsafe fn "))
            {
                let name = rest.split(['(', '<']).next().unwrap_or("").trim();
                names.push(name.to_owned());
            }
        }
    }
    let mut want: Vec<String> = TELEMENT_UNSAFE_FNS.iter().map(|s| (*s).to_owned()).collect();
    names.sort();
    want.sort();
    assert_eq!(names, want, "(a) stylo_host 内 unsafe fn 名集合必须恰等于上游 5 名、计数 == 5");
}

// (b) layout-backend/src/** 除 5 具名方法（+ 体内 ≤N 块）外，不得出现其他 unsafe 文本
#[test]
fn layout_backend_unsafe_surface_is_bounded() {
    let root = workspace_root();
    let mut fn_sigs = 0usize;
    let mut body_blocks = 0usize;
    let mut offenders: Vec<String> = Vec::new();
    for f in rs_files_in(&root.join("crates/layout-backend/src")) {
        let rel = f.strip_prefix(&root).unwrap_or(&f).to_string_lossy().replace('\\', "/");
        let is_bridge = rel.contains("/src/stylo_host/");
        for (i, line) in std::fs::read_to_string(&f).unwrap_or_default().lines().enumerate() {
            let code = code_part(line);
            if !code.contains("unsafe") {
                continue;
            }
            if is_bridge && (code.contains("unsafe fn ") || code.contains("pub unsafe fn ")) {
                fn_sigs += 1;
                continue;
            }
            if is_bridge && code.contains("unsafe {") {
                body_blocks += 1;
                continue;
            }
            offenders.push(format!("{rel}:{}:{code}", i + 1));
        }
    }
    assert!(offenders.is_empty(), "(b) 白名单目录外/非 5 名方法出现 unsafe 文本：{offenders:?}");
    assert_eq!(fn_sigs, TELEMENT_UNSAFE_FNS.len(), "(b) 桥内 unsafe fn 签名数须恰为 5");
    assert!(
        body_blocks <= STYLO_HOST_MAX_BODY_UNSAFE_BLOCKS,
        "(b) 桥内体内 unsafe 块 {body_blocks} 超上限 {STYLO_HOST_MAX_BODY_UNSAFE_BLOCKS}"
    );
}

// (d) layout-backend 文本无 v8::/extern crate v8（规则 5 等效补位）
#[test]
fn layout_backend_has_no_v8_type_escape() {
    let root = workspace_root();
    let mut hits: Vec<String> = Vec::new();
    for f in rs_files_in(&root.join("crates/layout-backend/src")) {
        let rel = f.strip_prefix(&root).unwrap_or(&f).to_string_lossy().replace('\\', "/");
        for (i, line) in std::fs::read_to_string(&f).unwrap_or_default().lines().enumerate() {
            let code = code_part(line);
            if code.contains("v8::") || code.contains("extern crate v8") {
                hits.push(format!("{rel}:{}", i + 1));
            }
        }
    }
    assert!(hits.is_empty(), "(d) 规则 5 补位：layout-backend 不得出现 v8:: 路径：{hits:?}");
}
