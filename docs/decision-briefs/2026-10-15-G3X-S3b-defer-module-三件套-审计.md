## §3 发现（「立即修」/「补记」）

2. **「补记」`T3`/`T2` 强化** —— **多 `<script defer>` ≥3** 的**文档序**用例（防「单条过、多条乱」）；已并入 **T2**（`['d0','d1','d2']`）。
3. **「立即修」`Message` 类型安全** —— 工程师称**复用 `Message`、token 携下标**；**若非枚举变体** ⇒ 建议 **`Message::Defer(...)` 变体区分**（防与既有消息通道**语义混淆**）。**请工程师在回报中说明现形态**（若已变体区分 ⇒ 记「已区分」）。**⚠️ 状态（主理人裁）= 待工程师回报现形态后裁**：**若为非变体 ⇒ 采 `Message::Defer(...)`**。
4. **「补记」改动面确认** —— 工程师版与我的 §10/增项**一致**（`parser.rs` **入队不进就地** + classic 不动；`page.rs` **load 内泵 defer 段 + DCL**；`engine-v8` **复用 `S3b-2` 边界 `perform_checkpoint()`**；`scheduler` **零改动**）⇒ **口径相符，无歧义**。

## §6 小对齐令回应（3 件，2026-10-15）

### ① `T7` **独立测试**（最高保真要求）
- **独立性**：**独立测试函数**（**不折叠、不并入 `T5`**），命名 **`timer_excluded_from_load_pump`**；
- **钉值**：**`load` 期间 `timer` 不触发**（`__fired == 0` 跨**整段 load 内泵**）；**`load` 返回后推进钟 ⇒ `timer` 正常触发**（**双向钉**）；
- **负对照**：**让 `timer` 参与 load 内泵 ⇒ `S3a` 的「load 后 `fired == 0`」门禁转红**（**判别性是它的存在理由**）；
- **最高保真**：**直取 `__fired` 计数 + 显式钟推进**（**不靠时序巧合**）。

### ② 概念 ↔ 测试名映射（含 `T2`/`T4` **合并表达的具名说明**）
- **`T2`** = `deferred_runs_in_document_order_as_tasks`（`__order == ['d0','d1','d2']`）—— **「as tasks」是双关**：既断**文档序**、又断**任务化**；**「是否真为任务（vs 同步）」由 `T1` 独立断**（**避免同名两义**）。
- **`T4`** = `dom_content_loaded_after_all_deferred`（**末位 = `'DCL'`**）—— 断**「`DCL` 在所有 defer 之后」**；**与 `T2` 分别覆盖「段内序」/「段末哨兵」**。
- **`≥3 defer`**：`T2` fixture **必须 ≥3 个 `<script defer>`**（`d0`/`d1`/`d2`），**防「单条过、多条乱」**。

### ③ `Message` 变体化（**裁定**）
- **规则（主理人裁）**：**非变体 ⇒ 显式载荷**；**不改 `scheduler` 枚举**。
- **✅ 裁定注落定（主理人 2026-10-15 亲验）= 「已区分」**：工程师以 **`DEFER_TOKEN_TAG` 显式区分** ⇒ **不新增变体、不碰 `scheduler` 枚举** ✓（**无需 `Message::Defer`**）。
- **架构师源级核可（2026-10-15）**：**形态核实** —— **`Message` 是 `TaskSource` 的枚举变体**（`scheduler/src/task.rs`），**无独立「载荷类型」** ⇒ 工程师判断**正确**（`Message::Defer{..}` **不可用**；**改它 = 动公共枚举**，与裁定 (b) 冲突）。现形态 = **`token = DEFER_TOKEN_TAG | 文档序下标`**；`run_task` **`raw & TAG == 0 ⇒ Done`**（非 defer 载荷**不由本分支处理**）。
  - **生产者核实**：`TaskSource::Message` 的**唯一产品码生产者 = defer（`page.rs:880`）**；`runloop.rs:448` 为 **`#[test]`** ⇒ **当前无冲突** ✓。**索引 `< 2^63`**（文档序）**天然满足**。
  - **✅ 认 —— 附 2 加固条件**：**(i) 文档化不变式**（**bit 63 保留给 defer**；**未来 `Message` 生产者不得置位**）⇒ 落 **`DEFER_TOKEN_TAG` 定义 + `TaskSource::Message` 文档**；**(ii) 补 1 判别测试** —— **非标签 `Message` token（如 `TaskToken::new(4)`）⇒ 不由 defer 分支处理**（`deferred` **不被取**）⇒ **把「防混淆」变机器断言**（**同 `T7` 精神**）。
- **状态**：**✅ 落定（附 2 加固条件 i/ii）**。
