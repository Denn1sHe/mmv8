## §9 网络语义与可插拔传输（M3 关联）

9 网络语义与可插拔传输
网络分成两个层次：NetworkService 实现页面可观测的 Fetch/XHR、Cookie、缓存与 origin 规则；Transport 只负责发送字节和返回响应。离线资源、Python 宿主请求和 Rust 在线传输共享同一状态机。reqwest 是 HTTP 客户端，不是 Chromium 网络栈。[S19]
后端
用途
必须说明的边界
OfflineBundle
社区版主路径与可重复测试
资源未命中进入等待或明确失败；允许宿主稍后注入。
HostTransport
接入现有代理、会话与 HTTP 客户端
通过 request_id 完成请求；不用 URL 唯一定位并发请求。
ReqwestTransport
原生在线 HTTP 服务
Rust 异步传输；不承诺 Chrome TLS/H2 特征。
CurlTransport 可选
需要指定传输配置的任务
封装 libcurl 或由宿主 curl_cffi 执行；逐版本验证特征。[S20]
ChromiumBackend 可选
必须获得浏览器网络整体行为
独立运行与计费/性能口径；不计入原生社区版兼容率。

接口契约
RequestSpec 保存 request_id、URL、method、重复可保留的 headers、body、initiator、credentials、redirect、signal 与导航代次。响应区分 headers 到达、body chunk、完成和错误；允许流式背压。Response bodyUsed、锁定、clone/tee、异常和取消由上层管理，不能用一次性的 Python dict 替代流状态。[S26]
Fetch 层处理 CORS、预检、opaque response、凭据、重定向与 forbidden headers；XHR 维护 readyState、响应类型、progress、abort 和 timeout。Cookie 存储统一管理 HttpOnly、Secure、domain/path、SameSite 与分区键；传输后端关闭独立 Cookie jar，防止双份状态漂移。[S27][S31]
用原始有序头列表保留多个 Set-Cookie；解压后的 body 与 Content-Encoding/Content-Length 的日志口径分别记录。ResourceTiming 区分实测与离线回放数据，不把虚拟值冒充真实 DNS/TLS 耗时。缓存和重定向决策由浏览器语义层统一拥有。
同步 XHR 的特殊处理
离线同步请求可直接查表；在线同步请求只能等待传输的纯数据完成，禁止完成路径依赖正在被阻塞的页面线程或 Python 调用线程。限制等待时间，错误与事件顺序按同步 XHR 分支实现。主线程同步 XHR 的规范限制与兼容模式差异分别标注。
netLog 记录发起、重定向、响应和失败，带 Cookie 快照、请求体引用与来源。高容量日志采用有界缓冲和按需导出，不在每个 chunk 上跨 Python 边界。

## §11 存储加密与文件能力（M1/M2 关联）

11 存储加密与文件能力
存储采用统一的 origin 分区
StorageService 管理 origin、top-level site、session 与持久化策略。localStorage/sessionStorage 的 key 顺序、字符串转换、配额、storage 事件与生命周期在内核实现。CookieStore 与 document.cookie 共享网络 Cookie 状态，而不是分别保存。离线执行默认使用内存存储，可显式导入导出快照。
IndexedDB 不是 SQLite API 的 JS 包装。Rust 实现 transaction、request、cursor、版本升级、key ordering 与自动提交调度，持久化后端可以使用 SQLite；CacheStorage 与 Storage Buckets 由同一分区管理。事件监听器与 Promise 的调度要参与事务存活判断。社区版对各接口的实际覆盖逐项冻结，真实完整 IDB 作为语义增强目标。
WebCrypto 保留算法库与 Web 接口的分层
优先以 aws-lc-rs 提供成熟密码实现，RustCrypto 仅补首选后端无法满足且已验证的算法。CryptoBackend 按算法暴露能力表，不假设某个库覆盖所有 WebCrypto 格式与模式。禁止自写 AES、RSA 或椭圆曲线算法。[S23]
Rust WebCrypto 层处理 AlgorithmIdentifier 归一化、CryptoKey 内部槽、extractable、usages、JWK/SPKI/PKCS8/raw 格式以及错误类型。覆盖 AES-GCM/CBC、RSA-OAEP/PSS、ECDH/ECDSA、HMAC/HKDF/PBKDF2 与摘要的社区版契约；ECC 签名格式、GCM tag 长度和 deriveBits 边界需专门测试。
getRandomValues 使用系统 CSPRNG，校验整数 TypedArray 类型与长度限制。SubtleCrypto 的计算交给受预算约束的后台任务，结果回页面线程 resolve。离线回放需要确定随机时，只允许在显式测试配置中替换熵源，不影响生产默认行为。
编码与文件以字节为底层
TextEncoder/Decoder 使用 encoding_rs 等成熟库并补 Web API 边界。Blob/File 保存 immutable 字节片段和类型元数据；FileReader 实现 readyState、事件、abort 与错误。URL.createObjectURL 关联 origin、存活引用和 revoke，不把 Blob URL 当普通网络 URL。
File System Access 提供 capability 限定的虚拟文件系统或指定目录后端；权限、handle 身份、异步迭代和写入提交行为分别验证。Clipboard、下载和设备接口通过显式 provider 注入，不允许页面凭任意字符串路径访问宿主文件。

## §12 图形媒体与设备扩展（M4 关联）

12 图形媒体与设备扩展
Canvas 2D 首选 Skia 而非固定返回值
用 skia-safe 接入 Skia，Rust 维护 Canvas 状态栈、路径、transform、裁剪、合成、图片数据和导出规则。字体文件、回退顺序、字形测量与页面文本策略保持一致，并用共同的字体清单验证。Skia 的存在不自动保证所有系统上的 Canvas 像素与 Chrome 一致。[S21]
Canvas measureText 与页面文本排版可能使用不同的 shaping 后端；要通过共用字体与测量测试限制差异。涉及字体或像素的基线同时记录 OS、字体哈希、设备缩放、后端版本与色彩设置。OffscreenCanvas 使用可转移资源所有权，禁止两线程同时写同一 surface。
WebGL WebGPU 与 SVG 分层实现
社区版兼容层按实测复制 WebGL/WebGL2 的参数、扩展、对象状态和错误行为；需要真实 shader、framebuffer/readPixels 时启用 ANGLE 后端。ANGLE 是 OpenGL ES 实现，仍需 WebGL 特有的校验、资源与安全规则，不是完整 WebGL JS 绑定。[S29]
WebGPU 先完成社区版实际暴露的接口契约；真实执行可选择 wgpu 或 Dawn 作为后端候选，再验证 WGSL、limits、error scope 和异步设备错误。不得把 native GPU 能力直接写成浏览器能力。SVG 元素、SVGAnimated* 与几何接口归 DOM/图形模块；SVG 渲染与文本独立列入扩展能力。
媒体与设备接口不能遗漏也不能虚报
建立统一 Provider 模型：NullProvider 按浏览器不支持或权限拒绝的真实分支返回；FixtureProvider 用于社区版既有模拟行为；NativeProvider 才接入真实设备。接口对象、状态变化、异常、Promise 和事件顺序均需进入社区版契约。
能力族
社区版覆盖路径
真实能力扩展
MediaElement / MediaStream
状态机、接口与离线 fixture
编解码、设备采集与播放另设后端。
Web Audio
节点连接、参数和既有离线行为
真实图计算、OfflineAudioContext、AudioWorklet。
WebRTC / WebCodecs
逐方法匹配已交付行为
独立会话/编解码服务，不能用空对象标完成。
WebSocket / WebTransport
离线连接 fixture 与状态/事件

重型原生依赖作为可选安装组件；默认 core 的功能标记清楚区分“可调用模拟”“离线行为”“真实计算”。社区版等价要求核对其真实行为，不能自行把未知功能降级为 NullProvider。

## §13 调试监控与环境配置（M5 宿主 CDP 域关联）

13 调试监控与环境配置
DevTools 分两部分建设
Runtime、Debugger、Profiler 和 HeapProfiler 优先接 V8 Inspector，保证局部变量、闭包、call frame 求值和单步行为来自真正的引擎调试器。暂停期间页面线程运行受控的 Inspector 消息泵，不推进普通页面任务，避免网络事件在暂停中任意改变页面。[S12]
宿主自行提供 DOM、CSS、DOMDebugger、Network、Page、Storage、DOMStorage、IndexedDB 与 Target 等所需域，并公布已支持的 method/event 清单。DOM 节点 ID 与真实 NodeId 映射；Worker 对应独立 target。Elements/Application 面板由这些域共同支撑，不能因为 WebSocket 连上就宣称完整 CDP。[S13]
监控提供兼容模式与低扰动模式
原生绑定生成器在 debug 构建中记录 getter/setter、构造和方法调用；日志按 API ID、参数摘要、时间、Realm 和调用位置组织。生产模式不安装 debug 拦截器，性能仍需测量，不能宣称数学上的零开销。
iv8 要求的 Object/Reflect/JSON/toString 访问日志通过显式 instrumentation 模式覆盖；该模式可能改变函数对象和调用栈，必须标记其可观测差异。低扰动模式只追踪原生浏览器入口。禁止使用全局 Proxy 捕获所有属性并声称语义完全不变。
API 访问断点在原生入口调用 Inspector break；XHR URL 和事件断点在对应状态机触发。禁用 debugger 暂停优先使用 Inspector 的 pause policy；vdebugger 兼容语法若必须转换，则用固定解析器和 source map，不做字符串替换。console、vconsole 与日志缓冲的权限分别定义。
环境画像是一份版本化契约
Profile 保存浏览器基线、OS、语言、时区、屏幕、字体、图形与网络策略；Schema 用 serde 校验，未知路径默认报错，兼容模式可警告。get_defaults 返回全部已注册路径与默认值，增量覆盖保持 iv8 习惯。
UA/UA-CH、Accept-Language、JS navigator 与请求头从同一画像生成；isSecureContext、crossOriginIsolated、permissions 由实际 origin 和策略派生，不能任意覆盖。环境字段可以配置，不代表底层支持任意浏览器版本。每个 Profile 的支持范围绑定测试基线。
debug/prod、规范/iv8 兼容模式、logical/system 时钟是独立维度。日志、类型转换、异常或安全策略不得因调试开关意外改变；不可避免的 instrumentation 差异单独输出。
