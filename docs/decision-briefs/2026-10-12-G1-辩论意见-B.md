## D1 · 句柄表与 GC 纪律

### 1. 我的独立结论

**选方案 B（弱引用槽表 + 显式租借），但按下列 3 点修正**：

- **修正 1（lease 语义）**：施工图 `HandleLease { handles: &mut HandleTable, .. }`（可变借用整表）
  **不可用**——持一个 lease 时无法 resolve 任何其它句柄、也无法同时持有第二个 lease。
  **改为**：槽存 `v8::Weak<Value>`（弱、可寻址），**`HandleLease` 自己拥有该值的 `Global`（强引用本体）**，
  lease **不借用**表（只携带 `(realm, handle)`）。Drop(lease) ⇒ drop(Global) ⇒ 值可回收。
- **修正 2（默认租借策略）**：`eval` 返回的对象必须**默认被 root**，否则宿主拿到句柄后随时失效（不可用）。
  落地：Python 侧载体 `PyJsRef { realm, handle, _lease: HandleLease }` **内持 lease** 即满足——
  「句柄非根」仍成立（根在 `PyJsRef` 内部的 lease，不在 `JsHandle`）。
- **修正 3（错误变体）**：`is_empty()` 触发（被 GC 回收）与 generation 不匹配（已释放/复用）是**两类**事件，
  必须**分开**：新增 `JsErrorKind::Collected`；`StaleHandle` 只用于 generation 不匹配。
  现施工图 `JsErrorKind`（§1.2 十个变体）**缺 `Collected`**。
- **附带**：`HandleTable` 若只用 `v8::Global::new` / `v8::Weak::new` / `to_global`（均**安全 API**），
  很可能可做到**零 unsafe**——把 SAFETY 面收窄到 scope/trampoline（施工图注「有 unsafe」或为高估，请工程师先确认）。
- **generation（子问题 3）**：**generation 计数足够**，无需「表级复用阈值」。但补两点：
  (i) 打包后 generation 为 u32，理论可回绕（2^32 次复用同一槽）——**槽回绕时退役该槽**（廉价，彻底消除 ABA）；
  (ii) `free` 必须 `generation += 1` 且清空 `weak`；`resolve` 比对完整 `(index, generation)`。

### 2. 决定性理由（各挂证据）

1. **§5「对象身份」原文**（技术方案）：*「断开的节点仍可能被 JS 持有，不能在 removeChild 时释放；
   节点池复用也不能让旧句柄指向新节点。」* 该条**同时**要求「host 侧不因 detach 释放 wrapper」（⇒ 不能强钉）
   与「复用防呆」（⇒ generation）。**只有弱引用 + generation 同时满足**；方案 A 强槽会让 `node_map`/wrapper
   被永久钉住，重演 ADR-0007 的 exp3（原文 `CYCLE_LEAK=true`，根因「`v8::Global` 正是 V8 的一个根」）。
2. **C-1 的字面只在 B 下成立**。ADR-0009 C-1 原文：*「`JsHandle` 不是 GC 根……不得是 `v8::Global` 的包装」*。
   A 下「持句柄 ⇒ 槽持 Global ⇒ 值被 root」，即**属性层面**「句柄即根」，与 C-1 冲突；
   B 下句柄=弱槽下标，**属性字面成立**。注意：C-1 的表示面（u64 下标）A/B 都满足，
   **分歧在属性面**——这正是 B 的正当性所在（而非 brief 所担心的「字面措辞」）。
3. **v8 152.2.0 API 实测（我 grep 源码核实，`src/handle.rs:785`）**：`v8::Weak<T>` 提供
   `is_empty()`、`to_global(&mut Isolate)->Option<Global>`、`to_local(scope)->Option`；GC 后 `is_empty()` 为真、
   `to_global` 返回 `None`（**回收后读取不 UB，是可判定的 `None`**）。同时：`Weak` 是 `!Send`/`!Sync`，
   且 *「is not supported on shared isolates」*。⇒ **B 技术可行**；但 `Weak::new` 需 `&mut Isolate`，
   施工图 `alloc(local, realm)` **参数不足**（A 下 `Global::new` 亦需 isolate，两者皆然，须补 isolate/scope 参数）。

### 3. 自我攻防（最强的反例 / 会改变结论的证据）

- **最强反例**：*「B 让 `eval` 返回的句柄**默认不可靠**（GC 时机不确定），对 Python 用户是灾难；
  A 简单且活/死**确定**，其实更实用——你为『C-1 字面』牺牲了可用性。」*
  该反例对「**裸 B**」成立；但**被修正 2 化解**（`PyJsRef` 内持 lease ⇒ 默认就是活的，A 的确定性收益被追平）。
- **会翻转我的结论的证据**：(a) 若实测证明「修正 2 后的 Python 用法」复杂度与 A 无差异，**但漏加 lease 的失败是静默的**
  （难以排查）⇒ A 更优；(b) 若 G1 短命单 Isolate 进程里 GC 几乎不触发，`handle_not_a_gc_root` 必须强制 GC 才变红，
  而强制 GC 在该构建下不可靠 ⇒ B 的可测性下降，应重新权衡。
- **须登记的诚实代价（C-4 尤其）**：修正 1 让 lease **可被多次持有**后，B 原本宣称的
  *「强引用环在类型上无法构造（lease 不 Clone）」* 这一**类型层面**优点**被削弱**。
  真正的防环改由 **C-2**（`web-dom`/`web-events` 类型面不得出现 `JsHandle`/**lease**，只许 `WeakJsHandle`）
  承担。⇒ **建议 ADR 把 C-4 的防环保证明确挂到 C-2 的类型面禁令上**，不要再依赖「lease 不 Clone」。

### 4. 被拒方案的残余风险（供登记）

- **方案 A（强引用槽表）**：`node_map`（C-3，在 `engine-v8` 内）若持强句柄，会**永久钉住** wrapper，
  且**门禁规则 5 抓不到**（泄漏点在白名单 crate 内部、类型面合法）⇒ 泄漏风险**内移**、失去外部可见性。
- **方案 C（混合：控制面强 / DOM 面弱）**：两套生命周期，「哪张表算根」退回**纪律**；残余风险 = 维护期
  把强表误用于 DOM 侧，正是 ADR-0009 想避免的形态。
- **裸 B（未修正版）**：`HandleLease { &mut HandleTable }` 下**同时至多一个 lease**；这是**功能性缺陷**，
  任何需要同时持两个 JS 对象的场景直接不可用——**若工程师照抄会立刻撞墙**。

### 5. 与 brief 推荐的异同

**部分修正**。方向一致（选 B）；但指出：① brief 的三条理由中「C-1 字面冲突」的**表述应精确化为「属性面冲突」**
（表示面 A 并不违反）；② brief 遗留的「`v8::Weak` API 待实测」**我已实测补齐**（可行，且 `to_global` 回收后返回 `None`）；
③ brief 未发现的**施工图 ↔ brief 互相矛盾**（A/B 混写）为阻断项；④ B 的可用性代价**比 brief 估计的大**（须修正 lease 语义）。

## D2 · PyO3 回调派发与 unsafe 归属

### 1. 我的独立结论

- **选方案 A（同线程直呼）作为 G1 落地形态**。G1 只做「Python 驱动 eval ⇒ 回调在该线程内直接派发」。
- **unsafe 归属：不改白名单、不移动 PyO3 边界**（采纳 U-1 实测）。D2 brief §6 的「若命中则选方案 C」**条件未触发**，
  故落「**不动作**」分支：`sdk-python` 保持 `[dependencies] pyo3`，ADR-0009 决策 2（转换放 `sdk-python`）**维持原样、无冲突**。
  方案 B（异步化）与方案 C（移边界）**均登记备查、本轮不做**。
- **补强 1（回调截止期限，§6 硬要求）**：技术方案 §6 原文 *「同步宿主回调必须有截止期限」*，
  而施工图**无此机制**（§3.6 的 `no_gil_wait_in_callback` 只测「派发不阻塞」，**不是**回调自身的期限）。
  **同线程下无法抢占正在运行的 Python 回调**（GIL 不可中断，ADR-0012 已证）⇒ 截止期限只能**检测+上报**、不能**强制打断**。
  **建议**：宿主在回调**进入前/返回后**做墙钟检查，超限 ⇒ 返回明确 `JsErrorKind`（如复用/新增 `CallbackDeadline`）；
  并**如实登记 G1 局限**：期限是「拒绝下一次/事后判定」而非「终止运行中回调」；上限的行使须来自 **Python 侧自带**
  （对齐 ADR-0012「Python 侧自持锁上限」范式）。**不要**把 `terminate_execution` 当作 Python 回调的期限手段（它打不到 CPython）。
- **补强 2（重入禁令）**：`Realm.in_callback` **必须 RAII**（guard 对象，panic/早返回都复位），
  且覆盖 **全部**重入入口（`eval`/`eval_module`/`perform_checkpoint`），专测「native fn → 再次 native fn」与
  「微任务期间隐式重入」两条路径。
- **措辞修正**：brief 与施工图称「回调内**不** `with_gil`」。精确表述应为**不发起跨线程的阻塞式取锁**。
  同线程已持锁时 `with_gil` 是重入的（ADR-0012 的死锁**只在跨线程互等**时发生）；且 `assume_gil_acquired` 是 **unsafe**，
  在 `sdk-python` 内被 `unsafe_code=forbid` **禁止**（U-1 已证 lint 武装）。⇒ 关键不变量是
  *「回调总在已持 GIL / 有活动 attach 状态的线程上执行」*，实现取 token 的具体调用不是判据。

### 2. 决定性理由（各挂证据）

1. **ADR-0012 实测原文**：GIL 路径 `GIL_BLOCKED_MS≈6000` 而 `WATCHDOG_FIRED_AT≈3000`，
   *「`terminate_execution()` 打断的是『正在 V8 里执行的 JS』，而 `Python::with_gil` 是在 CPython 内部等待，V8 看不见」*。
   A **结构上不存在**该路径（派发发生在已持锁的调用线程内，无跨线程等锁）；同行 `not_holding` 严格对照
   `GIL_BLOCKED_MS=0` 佐证「互等」是条件性的、可被 A 规避。
2. **U-1 实测（我复核 `probe-kit` 源码独立确认）**：`unsafe_code="forbid"` + pyo3 0.23 的
   `#[pyclass]/#[pymethods]/#[pyfunction]/#[pymodule]` **编译通过**（`p1b`/`p1d` = `Finished`），
   而注入显式 `unsafe {}` 报 `error: usage of an unsafe block`（`p1c`，`-F unsafe-code`）⇒ **lint 武装有效**。
   ⇒ `sdk-python` **不需白名单**、**不需移动 PyO3 边界**；brief §6 的 C 方案条件**未触发**，ADR-0009 决策 2 不变。
3. **方案 B 不具备 G1 判据资格**：ADR-0012 §遗留原文 *「`attach`/`detach` 异步化方案需另起 PoC 验证」*（**未实测**）；
   且异步化把「JS `f()` 同步取值」变成异步语义（技术方案 §16 原文本就是「拟定接口示例……由契约测试固定」），
   G1 上会超范围。

### 3. 自我攻防（最强的反例 / 会改变结论的证据）

- **最强反例**：*「A 依赖『回调总在持 GIL 线程上执行』这一不变量，但该不变量 **不在类型/运行时被强制**；
  一旦 G1 之外（watchdog 定时器、宿主消息泵、未来 Worker）有 JS 在别的线程触发 `py_callback`，
  A 的前提被破坏 ⇒ 无 GIL 调用 CPython C-API ⇒ 静默 UB。」*
- **会翻转我的结论的证据**：若证明 G1 内**存在任一非 eval 线程能触发 `py_callback`**（例如微任务由宿主 pump 在另一线程跑），
  则 A **不再安全** ⇒ 必须**对该不变量加运行时断言**（当前线程 id == eval 线程 id，违反即报错而非 UB）；
  若断言无法覆盖全部触发点 ⇒ 应回到 B。**这也是我给 G1 的强制补充项**。

### 4. 被拒方案的残余风险（供登记）

- **方案 B（attach/detach 异步化）**：引入专门线程 + 回填通道 ⇒ 新增**回调顺序、异常回填、close 时 in-flight 回调**
  三类时序问题；未实测 ⇒ **不得**作为 G1 的「安全」证据来源。
- **方案 C（PyO3 边界移进 `engine-v8`）**：`engine-v8` 引入 pyo3 依赖、unsafe 面扩大，且与 ADR-0009 决策 2 字面冲突。
  **本次未触发**，仅登记。

### 5. 与 brief 推荐的异同

**基本同意 + 补强**。主选择同（A）；unsafe 归属：brief 是「**先实测→若命中才 C**」的条件式，
而**实测未命中** ⇒ 我的结论更明确地落到「**不改**」分支（比 brief 少一层不确定性）；
**修正/补强 2 点**：① 必须补**回调截止期限**（§6 硬要求，施工图缺失）并如实登记「不可抢占」局限；
② 重入标志 **RAII + 覆盖全部入口**；③ 澄清「不 `with_gil`」的精确含义。

## 附 · 给 ADR 的强制动作项（按优先级）

   工程师在 ADR 落定前**不得**动 `handles.rs`。

4. **[登记]** D2 方案 B/C 为 G4 事项；D1 方案 A/C 残余风险（泄漏点内移 / 双真相源）入 ADR「被拒方案」章。
