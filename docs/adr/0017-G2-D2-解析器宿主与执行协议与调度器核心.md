## 问题

阻塞脚本的「暂停-执行-写回-恢复」如何组织 + 承载事件循环/消息泵/时序的 `scheduler` 核心形态。
两评审均**同意方案 A（任务化执行 + 单线程消息泵）**且确认 **U-1 源码级成立**（`rules.rs:746` →
`tree_builder/mod.rs:371` → `tokenizer/mod.rs:449`）；但指出「任务化 ≠ 可中断」、两处契约**不可编译**、
依赖环、`MutationObserver` 交付自相矛盾等。

## 决策

### 决策 1 —— 修依赖环（B-1，编译阻断）

两环：① `scheduler::TaskExecutor::run_task -> Result<_, PageError>` / `RunLoop::run_until -> Result<_, PageError>`
造成 `navigation ↔ scheduler` 双向；② `network::RequestSpec.epoch: NavigationEpoch`（定义在 `navigation`）
造成 `navigation ↔ network` 双向。修法：
- **①** `scheduler` **自持** `SchedulerError`（`scheduler/src/error.rs`）；`PageError: From<SchedulerError>`；
  `TaskExecutor`/`RunLoop` 的返回改 `Result<_, SchedulerError>`。**不采纳** `Box<dyn Error>`（丢类型，裁决书 §0.4）。
- **②** `NavigationEpoch` **下移共享层 `policy`**（`policy::NavigationEpoch`）；`navigation`/`network` 均依赖 `policy`
  （两依赖边已存在，**不引入新 crate**）。修后全图无环。

### 决策 2 —— **脚本任务接 watchdog 截断**（**定稿 · 采纳**，依据 P-1a）（A-B2 = B-3/断链 6）

「任务化」只界**任务数/任务间墙钟**，**不界任务内**。单个 `ScriptBlocking` 任务体内同步 `eval` 死循环 ⇒
`run_until` 永不返回 ⇒ 违 §6 docx:186「执行超时由独立 watchdog 请求 V8 终止」与 §16 docx:410「禁止 eval 悄悄无限等待」。

**P-1a 结论：可靠**（工程师实测，证据 `eval_watchdog_terminates_infinite_loop`，可复跑 3/3，engine-v8 **47 passed**；
延迟 ≈ grace + 2~5ms（实测 201~205ms @ grace=200ms）；打断后 `cancel_terminate_execution` 复位、`eval` 恢复可用、无污染）。
⇒ **定稿**：

- **公开形态**：`Realm::eval_with_deadline(&mut self, src: &str, deadline: Duration) -> Result<HostValue, JsError>`
  （内部 = G1 `perform_checkpoint` 同款 watchdog：独立线程 + 超时 `terminate_execution()` + `cancel_terminate_execution()`）。
  **`ScriptBlocking` 脚本任务 与 模块求值任务** 统一经它执行；上限 **设计意图**取 `RunBudget.deadline`（或独立 `script_deadline_ms`）——
  **⚠️ as-built（G2）为 `load` 期固定 2 s**（见文末「as-built 修正注记」）。
  （`Network` resolve / MO 交付若执行长脚本，一并经它。）
- **⚠️ 专有判据（P-1a 实测带出，必须落）**：当前 termination **与普通异常同 kind（`Exception`）、仅 message `"null"` 可辨识**
  ⇒ **复用既有 `JsErrorKind::Terminated`**（`error.rs:21`；语义「执行被 `terminate_execution` 打断（watchdog）」**完全一致**；
  **不新增变体**，避免同义重复）。**全链路映射**：
  ① `JsErrorKind` 变体清单 + **同步 `error.rs::ALL_KINDS` 穷举守卫**；
  ② **B-8 错误映射表**（`JsErrorKind::Terminated → PageErrorKind::Terminated`，**全链同名** → harness 可观测）；
  ③ **contracts**：**注意**——现有「两侧变体集合相等」断言（`test_v8_abi.py`）覆盖的是 **`HostValue` 变体**（非 `JsErrorKind`）；
  `JsErrorKind` **尚无**契约投影 ⇒ G2 **新增** `JsErrorKind` 投影面（`page_control.py` + 测试），**按既有变体集合（12 个，含 `Terminated`）**
  ——**无常量新增**；使 harness 可按**稳定前缀**断言「被打断」。
- **测试**：`stuck_script_terminated_by_deadline`（⇒ `Terminated`）；`engine-v8` 既有 `eval_watchdog_terminates_infinite_loop` 保留。
- **（原「不可靠 ⇒ 具名登记」分支作废**——P-1a 已证可靠；`capabilities.script_interruptible` **恒 `true`**。）

### 决策 3 —— 时钟与任务源（B-10/断链 8 + 跨源）

- **跨源顺序定稿**：`BTreeMap<TaskSource, VecDeque<TaskToken>>` 的**源间选择顺序**按枚举定义并**测试**
  （§6 只约束源内 FIFO；源间可观测 ⇒ 不得留白）。
- **逻辑时钟推进**：`run_until` 无立即任务时，**跳到最近的 due 定时器并执行**（**虚拟时间跳转、不 sleep**）。
  新增测试 `logical_clock_fires_timer`。`Clock::advance` 由 `RunLoop` 内部在跳转时调用（不再是「无调用者」）。

### 决策 4 —— `document.write`：post-load 具名错误 + 保序修正（A-B2 关联 / §3.3）

- **post-load 口径**：`document.write` 在 parser 已结束（`readyState != Loading`）时 ⇒ **具名错误
  `PageErrorKind::DocumentWriteAfterLoad`**（可判定、可测）。「清空并重开文档」**登记 G3+**。测试 `document_write_after_load_defined`。
- **多条 write 保序**：现形态（`pending_writes: VecDeque` + 逐条 `push_front`）会**倒置**
  （`write("a");write("b")` ⇒ `[b,a]`）。修正：`resume` 注入时**逆序 `push_front`**（或先拼接再注入），
  保证与**调用序**一致。**回归测试** `document_write_multiple_in_order`（落 ADR-0006「插入点顺序必须写成回归测试」射程）。

### 决策 5 —— `MutationObserver` 交付边界**一处定死** + **登记规范偏差**（A-§2.7）

三处描述不一致（brief「checkpoint 前」/ 施工图 §2.2「微任务 checkpoint」/ seq 图「checkpoint 后」）⇒ 必须收敛。
结构事实：**V8 不允许宿主把 MO 回调插进原生微任务队列**（`perform_microtask_checkpoint` 一次性跑完 V8 队列）⇒
宿主侧「前/后跑 MO」**都是规范偏差**。定稿：
> **MO 交付点 = 微任务 checkpoint 的宿主前段**（编排层先交付 owned 观察器记录 `mem::take` 出来、再 `perform_checkpoint`），
> 并**显式登记这是相对规范的偏差**（连同它与 Promise `then` 的相对顺序）。绑定一条纵向样例断言（§3.9 Promise→DOM→MO 链）。
（B-断链 10 序列① 要求 copy-out：`mem::take` 后释放借用再回调，回调期间新记录留下轮。）

### 决策 6 —— parked-awaiting-IO 任务态（B-9/断链 7）

`TaskVerdict::Requeue` 自旋会使队列永不为空 ⇒ `WaitingIo` **永不满足**（只会 `BudgetExhausted`）。定稿：
- 任务可被**出队停泊**（登记「等某 `RequestId`/promise」）；完成时**再入队**；
- **`is_idle()` 把「有停泊任务」计为「队列空」** ⇒ `RunOutcome::WaitingIo` **可达**；
- `WaitingIo` 定义精确化：**队列为空且存在停泊任务或未完成 I/O**。

### 决策 7 —— `BrowsingContext` 结构（B-2 + B-5）

- **字段改 `plane: engine_v8::control::ControlPlane`**（**不是**裸 `Realm`）——否则 `with_page_script`
  无从调用 ⇒ G1 已验收的 `ControlRevoked`/`inline_script_runs_in_page_scope` 在 G2 丢失。`realm_mut()` 经
  `plane.realm_mut()` 转发；**脚本任务体走 `plane.with_page_script(...)`**。
- **`ParserHost` 归宿**：作为 `BrowsingContext` 的字段（**不是** `PageShared` 内），生命周期由导航重建定稿
  （见 ADR-0018 决策「导航重绑」）；`finish(self)` 按值消费与 `self.tokenizer.sink.finish()` 层序一致。
- **批 2E 精化**：`BrowsingContext.shared` 定为**值持有 `PageShared`**（**非** `Rc<RefCell<PageShared>>`）——与细粒度借用规则
  一致、消除「`network()` 返回 `&mut` vs 外层 `RefCell`」张力；`PageShared` 中**跨 V8 回调共享的子单元**
  （`tree`/`writes`/`fetch_table`）为 `Rc<RefCell<…>>`，供原生闭包**直接捕获**；其余字段值持有。

### 决策 8 —— `run_until` 调用形态：解构 + 独立 executor（A-B3；seq 图修复）

`self.runloop.run_until(b, self)` 双重可变借用（E0499）。定稿（本仓既有先例 `realm.rs:267-272`）：
```rust
let Self { runloop, plane, shared, binding, .. } = self;   // 先解构
let mut exec = Exec { plane, shared, binding };            // 独立结构实现 TaskExecutor
runloop.run_until(budget, &mut exec)
```
**必须落进 §1.2/§2.1 与 seq 图**，否则工程师按图写不出。

### 决策 9 —— `NativeFn` 形态：**去 `+ Send`**（**定稿 · 采纳**，依据 P-1b）（A-B1）

`pub type NativeFn = Box<dyn FnMut(&mut Realm, &[HostValue]) -> Result<HostValue, JsError> + Send>`
（`native_fn.rs:36`）与 `PageBinding`/`__iv8_fetch` 需捕获 `Rc<RefCell<…>>`/`PageShared`（`!Send`）**互斥**；
`Realm::new_function`/`install_native_at` 是 `navigation` 注册原生函数的**唯一安全路径**（铁律 5）。

**P-1b 结论：去 `+ Send` 可行且已保留移除**（`native_fn.rs:40` 现为 `Box<dyn FnMut(...) -> Result<HostValue, JsError>>`；
全绿、**0 反例**；依据 = `Realm` 内含 `v8::OwnedIsolate`（`!Send`），`NativeFn` 只存于 `Realm.native_fns`，
整条链路本不要求 `Send`）⇒ **定稿**：
- **`NativeFn` 不再带 `+ Send`**（已落 `native_fn.rs`）；**不再需要侧通道**（原备选分支作废）。
- **`__iv8_fetch` 闭包可直接捕获 `Rc<RefCell<FetchTable>>`**（ADR-0018·D3 的归宿设计**不再受 Send 约束**）。

### 决策 10 —— `TreeSink` 全表面定稿（A-B6，S8）

`TreeSink::elem_name<'a>(&'a self, target: &'a Handle) -> ExpandedName<'a>`（`markup5ever-0.12.1/interface/tree_builder.rs:133`）
在 `DomSink{Rc<RefCell<NodeTree>>}` + `ElementData{name: String, namespace: String}` 下**无法实现**（返回类型须借住
interned atom，`RefCell::borrow()` 守卫在返回时亡）。定稿：施工图 §1.2 **展开 `TreeSink` 全部方法签名**
（原子名/精确 lifetime），并给出具体形态——**`DomSink` 侧维护 `HashMap<NodeId, QualName>` + `LocalName`/`Namespace`
atom 缓存**（或让 `NodeTree` 直接存 `QualName`）。**删除所有「…」省略**。同类 ~18 方法（`create_element(QualName,..)`、
`append_based_on_parent_node`（无默认实现）等）逐一落地。

### 决策 11 —— 错误映射表 + `JsErrorKind` 变体清单（B-8/断链 12）

新增**映射表**（`JsError(JsErrorKind) → PageError(PageErrorKind)`）+ **新增变体清单**，并**同步
`error.rs:71` 的 `ALL_KINDS` 穷举守卫**。新增（G2 拟定，最终以 S5/S13 定稿为准）：
`PageErrorKind::{ Terminated, DocumentWriteAfterLoad, TargetNotInDocument, StaleDocumentNode, NavigationAborted,
ModuleTopLevelAwaitUnsupported, Reentrancy, ... }`；**`JsErrorKind` 侧不新增变体**——**复用既有 `Terminated`**
（决策 2；`error.rs:21` 已存在，**`ALL_KINDS` 不变**）。
**契约同步（重要）**：现有「两侧变体集合相等」断言（`contracts/tests/test_v8_abi.py`）覆盖 **`HostValue` 变体**；
**`JsErrorKind` 变体尚无契约投影** ⇒ G2 在 `contracts/iv8_contract/page_control.py` **新增** `JsErrorKind` 投影 + 测试，
使 harness 可按**稳定前缀**断言「被打断 / 各类错误」（`Iv8Error`/`PageError` 消息前缀沿用 G1 口径）。

### 决策 12 —— 脚本任务错误路径矩阵（裁决书 §1.D2「架构细节」）

为 `ScriptBlocking`/`Network` resolve/`MutationObserver` 交付/模块求值各任务列出**完整错误路径矩阵**
（成功/`Terminated`/`Collected`/`Reentrancy`/`DocumentWriteAfterLoad`/模块失败），使每种错误**可在 `run_until` 观测**、
不得静默跳过。落 §1.2/§3.5。

### 模块脚本最小纳入（裁决书 §3，七条约束）

**纳入 G2 最小面**（K-11 已消解，ADR-0015）：
1. **暂停点对 `type` 无感** ⇒ 驱动在 `Script(node)` 处**先看 `type`**：classic ⇒ `ScriptBlocking` 任务；
   **module ⇒ deferred 列表 + 立即 `resume()`**，**永不在暂停点执行**（否则模块看不到其后的 DOM）。
2. 执行点 = **解析完成后、`DOMContentLoaded` 之前**，按文档序；**三条顺序回归测试**（classic-defer / module / DOMContentLoaded 相对序）。
3. **整图必须可同步解析**（OfflineBundle 同步查表）；未命中 = **可判定失败**（**绝不静默挂起**）；
   `module_resolver` 的 `None` 语义与解析失败区分（**ADR-0015 空返回纪律覆盖**）。
4. **TLA 在 G2 显式报错**（`PageErrorKind::ModuleTopLevelAwaitUnsupported`）——否则静默啃掉 `run_until` 有界性。
5. 模块求值任务同样受 **watchdog** 覆盖（决策 2）。
6. `import.meta` base URL：内联合成 URL 口径**登记**。
7. 失败必须**可在 `run_until` 观测**；**「模块 ≠ load-blocker（defer、不阻塞解析）」关系写清**。
> 落 §2.1/§3.2/§5 **S9b**（**已裁决纳入**，非条件步骤）。

## 后果

### 正面
- 全图**无依赖环**（B-1 闭合）；`ControlPlane` 归属与 `ParserHost` 归宿定稿（B-2/B-5 闭合）；
  调用形态可编译（B-3）；`TreeSink` 可写（B-6）；`document.write` 保序（B-7 关联）、MO 边界定死、逻辑时钟有推进者、
  parked-IO 使 `WaitingIo` 可达、错误可映射（B-8~B-10 闭合）。
- 模块脚本最小纳入有**明确约束**（不啃有界性）。

### 代价（如实登记）
- `scheduler` 新增 `SchedulerError`；`NavigationEpoch` 下移 `policy`（施工图 §1.1/§1.2/图需同步）。
- `TreeSink` 全表面展开 ⇒ S8 工作量上升（`DomSink` 需 atom 缓存）。
- 决策 2：watchdog 引入**每脚本任务的独立线程**（G1 同款代价，可接受）。
- 决策 9：`NativeFn` 去 `+ Send` ⇒ **`engine-v8` 公开类型面变更**（`native_fn.rs`），须复核无下游 `Send` 依赖（P-1b 已证 0 反例）。

## as-built 修正注记（2026-10-13 · 批 2G · 执行模型）

> **非语义修改**（如实记录**实现**与决策 2/5「任务化」描述的**差异**；经主理人确认**按 as-built 定稿**）。

- **实测形态**：**阻塞脚本在 `load` 内同步执行**（经 `Realm::eval_with_deadline`），上限 = **固定 2 s**
  （**非**设计原文「取 `RunBudget.deadline`」）；`run_until` 驱动 **网络 / MutationObserver / 输入** 任务泵与**微任务检查点**。
- **与 D2 设计的差异**：脚本**未经 `TaskSource::ScriptBlocking` 入队**（未走「任务化」执行）；
  「`run_until` 真正驱动页面 JS 事件循环（timer 驱动脚本）」**未实现**。
- **G2 为何可接受**：① §16「禁止 eval 悄悄无限等待」的**意图由 watchdog 兑现**（固定 2 s + `Terminated`），
  非「任务化」这一手段本身；② **验收测试均按此模型通过**；③ 任务化 / 事件循环驱动属**调度器完整形态**，本就登记于后续闸门。
- **延期项（登记，非缺陷）**：① **脚本任务化**（入 `ScriptBlocking` 队列，由 `run_until` 取预算驱动）；
  ② **timer 驱动的页面事件循环**。
- **不变项**：**决策 2 的 watchdog 部分不变**（仍采纳、仍 `eval_with_deadline` + `Terminated`）；
  **仅「由谁在何时调用 eval」按 as-built 调整**。
