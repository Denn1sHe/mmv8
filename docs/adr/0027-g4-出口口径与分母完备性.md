# ADR-0027：G4 出口口径、分母完备性与「遗漏九族」收口

- **状态**：**已定（2026-10-15）**；来源 = **主理人合并裁定包 `R-1`~`R-10`** + **评审书 A（证伪）/ B（从零）**；落地稿 = `docs/design-g4-真身-2026-10-15.md`（**v3 并稿**）。
- **章程依据**：`docs/iv8自研运行时完整技术方案.docx` §18（*"G4 平台能力闭环 … 通过后开展 清零社区版 `missing`/`unknown`"*）。

## §1 出口口径加严（**决定：加严，且显名**）

- **§18 原话**：「清零社区版 `missing`/`unknown`」是 **G4 通过后的「开展」**；
- **本仓决定**：**把「清零」前置为 G4 出口门禁（`G4-S6`）—— 加严**；
- **理由**：**可执行门禁优于文书口号**（沿用 G3X 由「G0 契约冻结」得出的同一判据）；**避免与 `G5`「全量 manifest 通过」同义反复** ⇒ **G4 出口 = `missing`/`unknown == 0`；`failed` 非零须逐条具名理由 + 白名单**。

## §2 出口与 `BLOCKING_STATUSES` 对账（**决定：对齐既有实现**）

- `contracts/iv8_contract/manifest.py:67-69`：`BLOCKING_STATUSES = {FAILED, MISSING, UNKNOWN}`、`is_release_blocking()`；
- **决定**：**G4 出口沿用该函式语义** —— **`missing`/`unknown` 归零为硬门禁；`failed` 允许非零但须「逐条具名理由 + 白名单」**（**消除「同仓两套阻断定义」**）。

## §3 分母完备性（**决定：外部锚定 + 双向核 + 冻结时点**）

- **分母定义源 = §18 接口清单**（**已机读落库**：`docs/refs/iv8-docx-G4-平台能力-提取-2026-10-15.md`）；
- **社区 `v0.1.4` 双模式实测（`cases` 的 `spec_expect`/`iv8_expect`）= 证据来源，非定义源**；
- **完备性验收（新增行 `4.7`）**：**`社区清单成员集 ⊆ manifest 成员集`**（**逐成员；未达显名 `missing`**）∧ **无清单外杜撰 `id`**（**双向核**）；
- **分母冻结时点 = `S0` 结束**（修正 `denominator_fixed` 语义）；
- **`G0` 欠账（无「冻结 `.md` 文书」）在 `M0` 显名登记** —— **「G0 契约冻结」的实质 = 机制（`manifest.py` + `cases`），非文书**。

## §4 「遗漏九族」收口（**决定：九族全部「进分母」，显名登记**）

`CacheStorage`/`Storage Buckets`｜`WebGL`/`WebGPU`/`SVG`/`OffscreenCanvas`｜`Web Audio`/`MediaStream`/`WebRTC`/`WebCodecs`｜编码文件与 URL｜`Streams`｜安全与权限｜设备与通信｜Worker 家族社区版契约｜`storage` 事件（跨文档）。

- **决定**：**九族全部「进分母」**（**社区契约层**，**保守最大集**，主理人 2026-10-15 照准）；**真实实现 ⇒ G6**；
- **纪律（主理人 2026-10-15 附）**：**`S0` 种子填充时，若发现某族与社区版 `v0.1.4` 实际面貌不符 ⇒ 以本 `ADR` 显式移出（具名理由）；不许静默删** —— **不得默默缺席**；
- **落点**：见设计 `§10` 收口表。

## §6 粒度续条（**成员定义 = WebIDL `.member`**；`R-3` 续；2026-10-15/16）—— **架构师草（待主理人审 → 入卷）**

### 6.1 「成员」定义

- **成员 = WebIDL 语义 `<Interface>.<member>`**（**含点**，**成员级**）：**属性 / 方法 / 常量 / 事件**（**四类**；**事件按 `on<name>` 记为接口成员**）。
- **与既有门禁对齐**：`manifest.py` 的 `"." in id` **强制** ⇒ **族级名（如 `"Window"` 无点）当场拒**；**跨族接口**（如 `SVGAnimatedLength.baseVal`）**同规则**。

### 6.2 进分母的接口族域（**兜底范围 = `§11`/`§12` 已具名族，不外扩**）

| 族（提取件已具名） | 候选接口（示例，**非穷举**） |
|---|---|
| **存储** | `Storage` / `StorageManager` / `StorageBucketManager` / `IDBFactory` / `IDBDatabase` / `IDBTransaction` / `IDBObjectStore` / `IDBIndex` / `IDBCursor` / `IDBRequest` / `CacheStorage` / `Cache` / `CookieStore` |
| **密码** | `Crypto` / `SubtleCrypto` / `CryptoKey` / `Algorithm` 系 |
| **图形媒体** | `CanvasRenderingContext2D` / `OffscreenCanvas` / `WebGLRenderingContext` / `WebGL2RenderingContext` / `WebGPU` 系 / `AudioContext` / `AudioNode` / `HTMLMediaElement` / `MediaStream` / `WebSocket` / `RTCPeerConnection` 系 |
| **编码文件** | `TextEncoder` / `TextDecoder` / `Blob` / `File` / `FileReader` / `URL` |
| **设备** | `Geolocation` / `Notification` / `Clipboard` |
| **宿主 CDP（`§13`）** | 域 × method/event（`Runtime.*` / `Debugger.*` / `DOM.*` / `CSS.*` / `Network.*` / `Page.*` / `Storage.*` / `DOMStorage.*` / `IndexedDB.*` / `Target.*`） |

> **防分母无界**：**只对提取件「已具名」的族枚举**，**不外扩**。

**🔎 §6.2 映射核对（设计 `§10` 九族 ↔ 本表兜底行；**逐族核对，无缺口**）**：

| 设计 `§10` 族 | 归属（本表兜底行） |
|---|---|
| ① `CacheStorage` / `Storage Buckets` | **存储** |
| ② `WebGL` / `WebGPU` / `SVG` / `OffscreenCanvas` | **图形媒体** |
| ③ `Web Audio` / `MediaStream` / `WebRTC` / `WebCodecs` | **图形媒体** |
| ④ 编码文件与 URL | **编码文件** |
| ⑤ **`Streams`** | **编码文件**（**字节/编解码面**；`§14`/`§15` 未单列 ⇒ **不扩表**） |
| ⑥ **安全与权限**（`Permissions`/`Trusted Types`/`CSP`/secure context） | **密码**（`§15` 同列「安全与权限｜policy/bindings」） |
| ⑦ 设备与通信 | **设备** |
| ⑧ **Worker 家族社区版契约**（`SharedWorker`/`ServiceWorker`/`Worklet`） | **宿主 CDP**（`§10` 独立成章；**社区契约层经宿主面暴露**） |
| ⑨ `storage` 事件（跨文档） | **存储**（`Storage` 成员） |

> **结论（写入本 `§6.2`）**：**六行 = 兜底枚举面**；**其外 3 族**（`Streams` / 安全与权限 / Worker 社区契约）**分别由「编码文件」/「密码」/「宿主 CDP」覆盖**（**不扩表**）—— **九族全落、无缺口** ✓（**回设计 `§10` 行名逐一对齐**）。
> **注（主理人 2026-10-15 裁 = **初判**）**：上表**三处「归属判」**（**⑤ `Streams` → 编码文件**｜**⑥ 安全与权限 → 密码**｜**⑧ Worker 契约 → 宿主 CDP**）= **初判**；**归属属「枚举覆盖面」的分类学** ⇒ **枚举实证后，若某成员无法落行 ⇒ 按纪律经本 `ADR` 修订（具名理由，**不静默改**）** —— **两源实证 + 纪律条款 = 该分类学的纠错回路**。

### 6.3 枚举方法学（**两候选源 + 可复现命令 + 版本锁定**）

- **候选 A（定义源·首选）= 社区 `v0.1.4` 实物自省**（**双腿并集，来源逐条可追**）：
  - **A-0「版本锁定」**：`iv8.__version__` + **逐文件 sha256** ⇒ `refs/community-v0.1.4-hash.txt`（**可证版本**）；
  - **A-1「Python 面」**：`inspect.getmembers(iv8.JSContext.__class__)` ⇒ `iv8.JSContext.<member>`；
  - **A-2「JS 面」**：**经社区版 `eval` 通道自省** `globalThis` 构造器 + `prototype` 成员 ⇒ `<Iface>.<member>`（**不依赖浏览器**）；
  - **前提**：维护者提供实物位置（**本仓 `poc/` = 我方 spike，非社区实物**）。
- **候选 B（兜底）= 规范面 WebIDL**：
  - **范围收窄**：**只对 `§11`/`§12` 已具名接口族**枚举（见 `6.2`），**不外扩**；
  - **IDL 抽成员命令**：**以 WebIDL 文本为输入，逐接口抽属性/方法/常量**（**纯文本、无外部依赖**）；
  - **锁定**：**`w3c/webref` commit SHA + 各 IDL sha256** ⇒ `refs/webref-hash.txt`；
  - **产出必带 `needs_community_review: true`**（**规范面非定义源，须显名待核**）。
- **产出格式（`load_members` 认可）**：`{ members[](非空), source, method(逐字命令), extracted_at, source_version, source_sha256, needs_community_review }` ⇒ **落 `contracts/community-v0.1.4-members.json`**；**复核标准 = 「同版本逐字复现」**。
- **A/B 执行序（硬）**：**A（社区实物）= 定义源，优先**（**等维护者回执**）｜**B 工具准备可先行**（**IDL 解析脚本 —— 只做工具，不落 seed**）｜**回执窗内无答复 ⇒ B 落 seed**（**`needs_community_review: true` 显名**）｜**A 后到 ⇒ 两源对账**（**"两源口径差 ⇒ 具名登记"条款正是为此**；**不静默取齐**）｜**任何移出 ⇒ 本 `ADR` 显式**（`§4`）。

### 6.5 `mixin` 合入语义（2026-10-16 补；`S0b` ⑤-4「要修」的规范依据）

- **规则**：**`interface X { … }; X includes M;`** ⇒ **`M` 的成员（属性 / 方法 / 常量 / 事件）归属 `X` 表面** ⇒ **以 `X.<member>` 记入分母**（**WebIDL 语义：mixin 成员被并入每个 includer 的接口面**）。
- **`mixin` 自身不作分母接口**（**`M` 非可实例化接口 ⇒ 无独立 `.member` 计数**；**避免重复计数**）。
- **不修的后果**：**`includes` 未解析 ⇒ 相关成员从 `X` 表面静默缺失** ⇒ **分母被静默剪小**（**`S0b` ⑤-4 裁「要修」之由**）；**修后成员数上升（`345 → 419`）+ 下界正确**。
- **枚举器须自证**：**mixin 合入前后「成员数差」= 可核量**；**变更入档，不静默**（**同族纪律：来源/成员数的变化必须显名**）。

- **纪律**：**禁用同名构造器补足计数**（docx 自证）；**粒度不可达 ⇒ 停报（不编造）**；**两源口径差 ⇒ 具名登记**；**任何移出 ⇒ 本 `ADR` 显式记录**（`§4`）。

## §8 生成物口径（**机器生成数据**；主理人 2026-10-15 裁）

- **范围**：**`members.json` 类机器生成数据**（如 `contracts/community-v0.1.4-members.json`）—— **超 400 行属预期**（**非手工编辑对象**）。
- **入档方式（**替代手工 diff 审阅**）**：**以「可复现命令 + 哈希锁」入档** —— **`method`（逐字命令）+ `source_version` / `source_sha256`**（见 `§6.3`）+ **`refs/*-hash.txt`**（**可证版本**）。
- **审阅口径**：**审「命令 + 哈希」，不审「逐行 diff」**（**数据体量大 ⇒ diff 无信息量；命令/哈希才是校验面**）。
- **纪律**：**机器生成物不得手工改**（**要改 = 改生成器**）；**生成器变更 ⇒ 重跑 + 哈希更新 + 具名登记**（**不静默**）。
- **台账**：**G4 活账 = `docs/g4-台账-2026-10-16.md`**（**进度 / 流水 / 索引**，**每断点随更**；**冻结文不动** —— 进度记台账，不入冻文）。

## §9 消歧与 `descriptor` 约定（**核可制度产出第 4、5 项**；主理人 2026-10-16 裁）

> **来源**：**架构师 `S1-a` 源级核可**（**非工程师自报**）发现两条**系统性**问题 —— **均已裁定**。

### 9.1 `descriptor` 真实化（**发现 ④ 裁定 = 修真**）

- **问题**：**全库 `descriptor` 仅 `attribute (1100)` / `constant (569)`，无 `operation`** —— **`Storage.getItem`/`setItem`/`removeItem`/`clear`/`key`（WebIDL `operation`）被标 `attribute`** ⇒ **`descriptor`（章程九字段之一）失真**。
- **裁定**：**抽取器 v2 出 per-member `descriptor` 四类** —— **`attribute` / `operation` / `constant` / `event`**（**CDP：`command → operation`、`event → event`**）⇒ **重跑三源 ⇒ 真实化** + **具名登记**。
- **约束**：**id 集合不变 ⇒ 分母冻结不受影响**（**仅 `descriptor` 值变**）。

### 9.2 「同名前缀双源约定」（**发现 ⑤ 裁定 = 保 id 忠实 + 三重消歧**）

- **问题**：**Web `Storage` 接口成员**（`Storage.getItem`…）与 **CDP `Storage` 域方法**（`Storage.clearDataForOrigin`…）**共用 `Storage.` 前缀** ⇒ **`Storage.*` 40 条混装两类**，**id 未编码来源域**（**未来真碰撞 ⇒ 双向核错判**）。
- **裁定**（**保 id 忠实**，**不重命名**）：
  1. **唯一性门禁**：**id 全局唯一**（**机器强制**；重复 ⇒ 红）；
  2. **`docs/refs/shared-prefix-report.md`**：**共享前缀清单**（**同前缀跨源**逐条具名登记）；
  3. **元数据承载**：**`realm` / `descriptor` 区分源域**（**不改 id**）。
- **约定名**：**「同名前缀双源约定」** —— **两源同名接口并存 ⇒ 以「唯一性门禁 + 共享前缀报告 + 元数据」三重消歧，严禁静默取齐/重命名**。
