## 问题

G1 的 `engine-v8` 要建**第一张句柄表**：宿主侧用一个轻量令牌（`JsHandle`）代表一个 JS 值，
使该值能跨越「JS 引擎 ↔ 宿主」的边界存活一段时间。要拍板：

1. 句柄表槽位存**强引用**（`v8::Global`，钉住值）还是**弱引用**（`v8::Weak`，不阻止 GC）？
2. 「宿主需要这个值活着」这件事由**持有句柄**隐式表达，还是必须**显式**申请租借？
3. 释放后复用槽位，旧句柄应报错还是静默指向新值？
4. 该形态能否逐条兑现 ADR-0009 的 **C-1~C-4**？

## 讨论要点（两位独立评审的**真实分歧**与采纳）

两评审在 **D1 方向**上出现真实分歧：

| 维度 | 评审 A（对抗性证伪） | 评审 B（从零评估） | 主理人裁决 |
|---|---|---|---|
| 槽表示 | 主张**强槽**（方案 A）；认为 brief「A 与 C-1 字面冲突」是**误读** | 主张**弱槽**（方案 B）；认为 C-1 冲突在**属性面**真实存在 | **采纳 B（弱槽）** |
| A 的关键论点 | **D1.2-1**：C-1 原文约束的是「`JsHandle` 这个**类型本身**的实现」，其判据是「`JsHandle` 的 impl 中禁止出现 `Global::new`」；A 下 `Global::new` 在 `HandleTable::alloc`，**不在 `JsHandle` impl** ⇒ A **表示面**满足 C-1 | **D1.5 / §2 理由 2**：C-1 的分歧在**属性面**——A 下「持句柄 ⇒ 槽持 Global ⇒ 值被 root」即「句柄即根」，与 C-1 保护意图冲突 | **采纳「属性面阅读」为约束解释**（见决策 7） |
| A 的 A+ 变体 | **D1.1**：强表 + `WeakJsHandle` 弱通道（强表只承载不参与跨语言环的值，DOM 面强制走弱） | — | **未采纳**（理由见决策 8） |
| 共同点 | 二人都指出：**C-4 的「防跨语言环」不能靠 `HandleLease` 不 `Clone`**（跨层错配，ADR-0007 的环是 cppgc↔V8 跨堆环，不是 Rust 所有权环）；真正防环在 **C-2** | 同左 | **采纳：C-4 防环改挂 C-2**（决策 6） |
| A 的证伪成果 | 攻破 brief 两条理由：①「A 与 C-1 字面冲突」（表示面实不违反）；②「lease 不 Clone 防环」（跨层错配） | — | **已吸收**（决策 6、7） |
| B 的契约修正 | — | **修正 1/2/3**：lease 语义、默认租借、错误分类 | **全部采纳**（决策 1/2/3） |

> **评审 A 未能完全证伪 B**：其自陈「B 的『无任何强句柄 ⇒ 不可能误 pin 成环闭包』这一**结构性优点**，
> 我没能攻破；我只证伪了它**给出的理由**」（`辩论意见-A.md` §D1.3）。
> **这构成本 ADR 采纳 B 的核心依据**：B 的理由被更正，但 B 的**结构性优点仍然成立**。

## 决策

**采用方案 B（弱引用槽表 + 显式租借）**，并吸收评审 B 的三处契约修正与两位评审的精确化要求。

### 决策 1 —— lease 语义（修正 1，评 B 提出）

`HandleLease` **自己拥有该值的 `Global`（强引用本体）**，**不借用整表**。
施工图原形态 `HandleLease { handles: &mut HandleTable, .. }`（可变借用整表）**不可用、作废**：
持一个 lease 时无法 resolve 任何其它句柄、也无法同时持有第二个 lease（功能性缺陷，评 B §1 修正 1）。

- 槽位存 `v8::Weak<v8::Value>`（弱、可寻址）。
- `HandleLease` 只携带 `(realm, handle)` + **拥有的 `Global`**。
- `Drop(lease)` = drop `Global` = 取消 rooting ⇒ 值可回收。

```rust
struct Slot {
    generation: u32,
    weak: v8::Weak<v8::Value>,       // 弱：不阻止 GC
}

pub struct HandleTable {
    slots: Vec<Slot>,
    free: Vec<u32>,
    realm: RealmId,
}

impl HandleTable {
    pub fn new(realm: RealmId) -> Self;

    /// 登记一个值：建槽、存**弱引用**。`isolate` 参数必需（`Weak::new` 需 `&mut Isolate`）。
    pub fn alloc(&mut self, isolate: &mut v8::Isolate, local: v8::Local<v8::Value>)
        -> Result<JsHandle, JsError>;

    /// 解析：比对**完整** `(index, generation)`；弱已空 ⇒ `Collected`（见决策 3）。
    pub fn resolve<'s>(&self, scope: &mut v8::PinScope<'s, '_>, h: JsHandle)
        -> Result<v8::Local<'s, v8::Value>, JsError>;

    /// 释放：清空 `weak` + `generation += 1`（见决策 4）。
    pub fn free(&mut self, h: JsHandle) -> Result<(), JsError>;

    /// close 时排空全部槽位（§4：释放宿主回调与句柄）。
    pub fn drain(&mut self);
}

/// 显式租借：**自己拥有该值的 `Global`（强引用本体）**，不借用表。
pub struct HandleLease {
    realm: RealmId,
    handle: JsHandle,
    global: v8::Global<v8::Value>,   // 强引用本体；Drop 即取消 rooting
}
impl HandleLease {
    pub fn realm(&self) -> RealmId;
    pub fn handle(&self) -> JsHandle;
}
impl Drop for HandleLease { fn drop(&mut self); }
```

`Realm` 侧入口：

```rust
impl Realm {
    /// 显式获得强引用：从弱槽 `to_global` 得到 `Global`，包成 `HandleLease`。弱已空 ⇒ `Collected`。
    pub fn root(&mut self, h: JsHandle) -> Result<HandleLease, JsError>;
    /// 弱句柄（供 DOM 面 / node_map 使用，不阻止 GC）。
    pub fn weak(&mut self, h: JsHandle) -> Result<WeakJsHandle, JsError>;
}
```

### 决策 2 —— 默认租借（修正 2，评 B 提出）

`eval` 返回的对象必须**默认被 root**，否则宿主拿到句柄后**随时失效**（对 Python 用户是灾难，评 B §3）。
落地：Python 侧载体 `PyJsRef` **内持 lease** ⇒ 默认存活且可用；
**「句柄非根」仍成立**（根在 `PyJsRef` 内部的 lease，**不在** `JsHandle`）。

```rust
#[pyclass]
pub struct PyJsRef {
    realm: RealmId,
    handle: JsHandle,
    _lease: HandleLease,   // 内持租借 ⇒ Python 侧默认存活；Drop 即释放
}
```

**Rust 引擎内**跨调用存活必须**显式** `root()`（不自动 root，避免「句柄即根」隐式回归）。

### 决策 3 —— 错误分类（修正 3，评 B 提出）

`is_empty()` 触发（**被 GC 回收**）与 generation 不匹配（**已释放/复用**）是**两类**事件，必须分开：

| 事件 | 错误变体 |
|---|---|
| 弱引用已空 = 值被回收 | **新增 `JsErrorKind::Collected`** |
| generation 不匹配 = 已释放/复用 | `JsErrorKind::StaleHandle`（**只**表此意） |

**两类分开测试**（施工图 §3.4 增 `collected_detected`，与 `stale_handle_detected` 并列）。
`error.rs` 须同时含 `Collected` 与 D2 的 `CallbackDeadline`（见 ADR-0014）。

### 决策 4 —— generation（子问题 3）

**generation 计数足够**（评 B §1「附带」），无需「表级复用阈值」。补两点：

1. **槽回绕退役**：打包后 generation 为 u32，理论可回绕（2^32 次复用同一槽）——
   **回绕时退役该槽**（廉价，彻底消除 ABA）。
2. `free` 必须 `generation += 1` **且清空 `weak`**；`resolve` 比对**完整** `(index, generation)`。

### 决策 5 —— alloc / resolve 补 isolate/scope 参数

`v8::Weak::new` 需 `&mut Isolate`、`to_global` 需 `&mut Isolate`、`to_local` 需 scope
（评 A §0 F1、评 B §2 理由 3，二人均指出施工图签名缺参）。
⇒ `HandleTable::alloc` **补 `isolate: &mut v8::Isolate`**；`resolve` **补 `scope: &mut v8::PinScope`**
（签名见决策 1，已在施工图 §1.2 同步重写）。

### 决策 6 —— C-4 防环**改挂 C-2**（两评审共识）

**埋葬**「`HandleLease` 不 `Clone` 故强引用环难构造」的说法——这是**跨层错配**：
ADR-0007 的环是 cppgc 宿主对象 ↔ V8 闭包的**跨堆环**，不是「两个 Rust lease 互相捕获」的
Rust 所有权环。修正 1 让 lease 可被多次持有时，该「类型层面优点」进一步削弱（评 B §3 诚实代价）。

**C-4 的防环保证 = C-2 的类型面禁令 + 评审**：

> `web-dom` / `web-events` 的类型面**不得**出现 `JsHandle` / `HandleLease`；
> 事件监听器槽只允许 `NodeId`（整数）或 `WeakJsHandle`。
> `node_map`（C-3，在 `engine-v8` 内）持 **`WeakJsHandle`**，不持强 `JsHandle`。

### 决策 7 —— C-1 的约束解释（ADR 必须记录）

- **评 A 的文本阅读**：C-1 只约束「`JsHandle` 类型的实现」（判据：`JsHandle` 的 impl 内不得出现
  `Global::new`）；A 下 `Global::new` 在 `HandleTable::alloc`，故 A **表示面**满足 C-1。
- **评 B 的属性阅读**：C-1 的保护意图是「**持裸句柄不得等效于持根**」；A 下「持句柄 ⇒ 值被 root」，
  属性层面即「句柄即根」，与该意图冲突。

**裁决：采纳「属性阅读」为约束解释。** 理由：

1. **B 形态同时满足两种阅读**（表示面：句柄是 u64 下标；属性面：持句柄不 root）⇒ 无争议、更稳。
2. **A 的残余风险与该条保护意图相悖**：强默认形态下 `node_map` / wrapper 会被**永久钉住**，
   泄漏点**内移**到 `engine-v8` 内部、且**门禁规则 5 不可见**（类型面合法）——这正是 C-1 想防的
   ADR-0007 复现形态（`CYCLE_LEAK=true`）。
3. **未采纳评 A 的 A+ 变体**（强表 + 弱通道）：它把「不参与跨语言环」这一性质**退回纪律 + 门禁**，
   而强表是否真的只承载「安全值」无法在类型上保证；B 从结构上**不存在**误 pin 成环的可能（评 A 未能攻破此点）。

### 决策 8 —— 被拒方案及残余风险（供登记）

| 被拒方案 | 残余风险 / 未采纳理由 |
|---|---|
| **方案 A（强引用槽表）** | `node_map`（C-3）若持强句柄会**永久钉住** wrapper；**泄漏点内移**、门禁规则 5 抓不到；与 C-1 属性面冲突 |
| **方案 A+（评 A：强表 + 弱通道）** | 「强表只承载不参与跨语言环的值」退回**纪律**，类型上不可保证；弱通道与「节点映射一律弱」的边界需额外门禁 |
| **方案 C（双表：控制面强 / DOM 面弱）** | 两套生命周期、「哪张表算根」退回**纪律**（正是 ADR-0009 想避免的形态）；维护期可能把强表误用于 DOM 侧 |
| **裸 B（未修正版，`HandleLease { &mut HandleTable }`）** | 同时至多一个 lease ⇒ **功能性缺陷**，需两个 JS 对象的场景直接不可用（评 B §1） |

> **记录评审 A 的证伪成果（已吸收）**：其攻破的「brief 的 C-1 字面理由」与「lease 防环」两条，
> 分别由**决策 7（属性阅读 + A/A+ 未采纳理由）**与**决策 6（C-4 改挂 C-2）**吸收。

### 决策 9 —— 附记：`HandleTable` 很可能**零 unsafe**

`HandleTable` 主体若只用 `v8::Global::new` / `v8::Weak::new` / `to_global`（**均安全 API**），
**很可能可做到零 unsafe** ⇒ SAFETY 面收窄到 scope / trampoline。
**写成「待工程师实确认」**：若成立，施工图 §1.2 对 `handles.rs` 的 unsafe 标注应更正为「**零 unsafe**」
（`engine-v8` 的 unsafe 仅剩 `isolate.rs` / `native_fn.rs` / `realm.rs` / `control.rs` 的 V8 构造点）。

> **实测结果注（2026-10-12 · S5 验收）**：**已确认** —— `handles.rs` **零 unsafe**（模块文档
> `handles.rs:10`「零 unsafe」；只用 `Weak::new`/`to_local`/`to_global`/drop 安全 API）。
> 且 S6 的 `isolate.rs` / `realm.rs` 亦**零 hand-written unsafe**（`realm.rs:11`
> 「不含手写 `unsafe`」；`isolate.rs` 无 `unsafe` 块）⇒ SAFETY 面**收敛到 S7+ 的 scope / trampoline**。
> 施工图 §1.1/§1.2 的 `handles.rs`/`isolate.rs`/`realm.rs` unsafe 标注**已同步更正为「零」**。

## 后果

### 正面

- 同时满足 C-1 的**表示面与属性面**两种阅读，无争议。
- **不存在**「句柄即根」的隐式回归；误 pin 成环在 B 下**结构上不可达**。
- 兑现 C-2 / C-3：DOM 面只走 `WeakJsHandle` + `NodeId`，`node_map` 持弱句柄。
- `Collected` 与 `StaleHandle` 分离，使「失效」是**可判定的错误**而非静默错误值（对齐铁律 10）。

### 代价（如实登记）

1. **B 的可用性代价比 brief 估计的大**：必须靠**修正 2（默认租借）**才可用；
   Python 侧由 `PyJsRef` 内持 lease 满足，**漏加 lease 的 Rust 用法会失效**（评 B §3）。
2. `v8::Weak` **`!Send`/`!Sync`**，且 **`is not supported on shared isolates`**
   （`handle.rs:879-887` 原文 assert）⇒ **G4 的 `SharedIsolate` 路径天然受限**（登记为 G4 事项）。
3. 弱槽回收路径依赖 GC 终结行为，而对终结回调 V8 明文「**不保证何时、甚至是否被调用**」
   （ADR-0007 已引）⇒ 回收的**时机不可依赖**，须用「事后判定」而非「准点回调」。

### 待实测登记（进施工图对应步骤）

| # | 待实测项 | 落点 |
|---|---|---|
| T1 | `Weak` 回收后 `to_global`/`to_local` → `None`（**可判定、非 UB**） | S5 / S9 测试（`collected_detected`） |
| T2 | **强制 GC 手段的可靠性**（`--expose-gc` / `request_garbage_collection_for_testing`） | S5 / S9（`handle_not_a_gc_root` 需强制 GC 才可判定） |
| T3 | `Weak` 的 `!Send`/`!Sync` 与「shared isolate 不支持」落实到**类型设计注记** | S5（`handles.rs` 类型注记） |

> **实测结果注（2026-10-12 · S5 验收 · 非语义修改，样式对齐本仓「修正注记」纪律）**：
> **T1 已实测通过** —— 手段 `scope.request_garbage_collection_for_testing(GarbageCollectionType::Full)`；
> 结果：`Weak` 回收后 `to_local`（`resolve` 侧）与 `to_global`（`root` 侧）**均返回 `None`** ⇒ 报
> `JsErrorKind::Collected`，**可判定、非 UB**（源码 `crates/engine-v8/src/handles.rs:274-298`，测试
> `collected_detected`）。**T2 已实测**：该强制 GC 手段在本构建下可靠（`handles.rs:265`）。
> **T3 仍待（G1 收尾复核）**：`Weak` 的 `!Send`/`!Sync` 与 shared isolate 约束**尚无** `handles.rs` 专门
> 类型注记；该约束在 G1 仅**间接**体现在 `PyContext: unsendable`（`crates/sdk-python/src/lib.rs:75-76`）
> 与 `Isolate: !Send`。**保留为 G4（`SharedIsolate`）前需补的登记项**——按 ADR-0014 的 `!Send` 结论，
> G1 单线程形态不受影响。

### 遗留（本 ADR 不做）

- **跨堆追踪（ephemeron）的 unsafe 桥接**：ADR-0007 遗留，需另起 PoC（本轮不做）。
- **G4 的 `SharedIsolate` + `Weak` 冲突**：新登记（本 ADR 由 T3 带出）。

## 附：本 ADR 对施工图初稿（§1.2 `handles.rs`）的更正

施工图初稿 §1.2 写的是 **强槽**（`Slot { value: Option<v8::Global> }`）+ `HandleLease { &mut HandleTable }`，
与本文**两处均冲突**（评 A D1.5、评 B §0 阻断性发现）。**本 ADR 为准**，施工图 §1.2 已同步重写为
**弱槽 + 自持 `Global` 的 lease**。**工程师在 ADR 落定前不得动 `handles.rs`**（评 B 附·动作项 1）。
