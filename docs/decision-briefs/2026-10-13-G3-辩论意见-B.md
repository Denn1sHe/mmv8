## ① 结论：**有条件支持**（方向支持，S1 前须闭合 §3 的 5 条高危阻断项）

- **方向正确**：切「直连 Stylo + Taffy + Parley」是 ADR-0011 已裁路线；施工图
  §0.2 目标集合（样式复用/布局复用/字体/动态失效/Shadow/几何 stub→真实）**逐一对应** §18 的
  G3 必产出（`HANDOFF-2026-10-13.md:68`），没有缩水到一半（Shadow 明确含作用域隔离 + slot + 布局参与，
  `design-g3-layout-2026-10-13.md:426-435`），也没有把 G4 的动画/滚动/命中测试塞进来
  （`:101-108` 显式登记）。**「不通过判据」（`R11`，`:658`）可判**（`SHADOW_SCOPE_WORKS==false`
  或 `GEOMETRY_MATCHES_EXPECTED==false` 或 `FONT_DETERMINISTIC==false`），这一点比 G2 更硬。
- **但**：施工图把若干**未证的硬假设**当作事实写进了「零 unsafe 纪律」（`:35-36/:123-124/:720`），
  且**函数签名级契约存在可直接编译失败的缺口**（§3 B2/B3/B7）。若不在 S1 前闭合，
  S1 探针会以「编译不过」的形态连续失败，浪费一轮。
- **结论落点**：**支持 D1（立即启动直连路线）但必须以「修正后的 S1 三探针」为前置门**；
  D2/D3/D4 我同意各 brief 的推荐方向（见 §5），但对 D4 的「timer 归 G3」持保留（§5）。

## ③ 阻断项清单（问题 / 证据 / 建议）

> 分级：**P0 = S1 前必须闭合**（否则探针/编译必失败或判据假）；**P1 = S2 前闭合**；**P2 = 登记/低危**。

### B1（P0）`OpaqueElement`/`opaque()` 反水化 —— 「零 unsafe」与「可实现全套 trait」不可兼得（最高危）
- **问题**：stylo 的 `TElement` 要求 `selectors::Element`，而 `Element::opaque(&self) -> OpaqueElement`
  **是必需方法、无默认实现**；`TShadowRoot` 作用域又要把 `OpaqueElement` **反水化**回宿主元素。
  施工图把「`NodeRef<'a>{tree,id}` 可零 unsafe 实现全套 trait」当作**已定事实**，而 P-1/P-4 的判定里
  **完全没有**这一步。
- **证据（源码原文）**：
  - `selectors-0.40.0/tree.rs:17` `pub struct OpaqueElement(NonNull<()>);`
  - `selectors-0.40.0/tree.rs:24-32` `pub fn new(...) { unsafe { OpaqueElement(NonNull::new_unchecked(...)) } }`
  - `selectors-0.40.0/tree.rs:46-50` `pub trait Element: Sized + Clone + Debug { … fn opaque(&self) -> OpaqueElement; }`（**无默认**）
  - `stylo-0.20.0/dom.rs:409-410` `pub trait TElement: … + SelectorsElement<Impl = SelectorImpl> + ElementContext`
  - `stylo-0.20.0/dom.rs:976-981` `fn implicit_scope_for_sheet_in_shadow_root(_opaque_host: OpaqueElement, …)`
  - 施工图：`:267-275`（NodeRef 即插即用）、`:123-124`/`:35-36`/`:720`（零 unsafe 硬断言）
- **风险**：`NodeRef<'a>` 是**借用视图**（含 `&'a NodeTree` 生命周期），无法安全地交出指向自身的
  `NonNull`（会悬垂）。可行解只有三条：(a) 用 arena 槽的**稳定地址**（但 `NodeTree` 用
  `Vec<Option<NodeData>>`，`push` 会**重分配** ⇒ 地址不稳，见 `tree.rs:14-20,72-76`）；
  (b) 一张 `id → &Node` 的**侧表**（正是施工图 `:339/:657` 用「无第二写点」纪律禁止的东西）；
  (c) `unsafe`（与「零 unsafe」断言冲突）。
- **建议**：
  1. **把「opaque/rehydrate 的实现路径」提升为 P-1 的一部分**（而不是留给 P-4 的 `::slotted` 行为），
     判定标准加三条：**不引入 unsafe**、**不建 id→node 侧表**、**arena 地址可稳定**（或明确改用
     `Box<NodeData>`/`stable_deref` 级别的稳定槽）。
  2. 若实测必须 unsafe ⇒ **预先在 ADR-0021 里开一条 `layout-backend` 白名单**并写 `// SAFETY:`，
     不要等到 S1 才发现与铁律 2 冲突（`AGENTS.md` 白名单是**结构性**约束）。
  3. 探针形态：直接调 `stylo` 的匹配 API 验证作用域，**不要经 JS `querySelector`**（见 B5）。

### B2（P0）依赖与 trait 路径写错：`stylo_dom` 里没有 `TNode/TElement/TShadowRoot`
- **问题**：施工图与 brief 反复把 trait 归到 `stylo_dom`，并把它列进依赖（`:487`）。实际
  `stylo_dom 0.20.0` **只有两个 bitflags**，没有任何 trait；trait 在 `stylo`（包名 stylo，import
  名 `style`）的 `dom` 模块。工程照抄会得到 `error[E0433]: failed to resolve … stylo_dom::TNode`。
- **证据**：
  - `stylo_dom-0.20.0/lib.rs`（全长 196 行，只有 `ElementState`/`DocumentState` + `malloc_size_of_is_0!`）
  - `stylo-0.20.0/dom.rs:153` `pub trait TNode`、`:364` `pub trait TShadowRoot`、`:409` `pub trait TElement`
  - `stylo-0.20.0/Cargo.toml`：`name = "stylo"`、`[features] default = ["servo"]`、`build = "build.rs"`、`links = "servo_style_crate"`
  - 施工图 `:270,:274`；brief `stylo-direct.md:55-57`；`:487`
- **建议**：把直接依赖改成 `style = { version = "=0.20.0", package = "stylo" }`（brief 证据 B 已如此锁定），
  trait 路径写 `style::dom::*`；`stylo_dom` 仅在需要 `ElementState` 时保留。同时在 §2.4 注明
  **stylo 需 `servo` feature + build.rs 产物**（`stylo_static_prefs`/`stylo_atoms` 传递引入），
  避免 S2 才踩到。

### B3（P0）`LayoutBackend` 缺 `: Debug` ⇒ `BindingInputs` 派生 `Debug` 直接编译失败
- **问题**：施工图把 `layout: Rc<RefCell<Box<dyn LayoutBackend>>>` 加进 `BindingInputs`（`:345-349`），
  但 `BindingInputs` 与 `PageBinding` 都 `#[derive(Debug)]`；`Box<dyn LayoutBackend>` 要满足
  `Debug` 需 `dyn LayoutBackend: Debug`，而 trait 定义（`:194`）没有此约束。
- **证据**：`crates/navigation/src/binding.rs:47` `#[derive(Debug, Clone)] pub struct BindingInputs`；
  `:66` `#[derive(Debug)] pub struct PageBinding`；施工图 `:194`、`:345-349`
- **建议**：`pub trait LayoutBackend: std::fmt::Debug { … }`（并在 §3 加一条「门面 trait 对象可用
  `Debug` 打印」的编译断言）。这是**改一行、省一轮**的典型。

### B4（P0）§3.2 的 `clientWidth==94` 算错，且与 §3.4 自相矛盾
- **问题**：`width:100px; border:2px; padding:3px; box-sizing:border-box` 时，
  border-box 宽 = 100，左右 border 共 4px ⇒ `clientWidth`（padding box）= **96**，不是 94。
  而 §3.4 又规定 `clientWidth == offsetWidth - 左右 border`（=100-4=96）。**两处契约互斥**，
  测试先行会先写死一个错值。
- **证据**：施工图 `:523`（`clientWidth==94`）vs `:542`（`offsetWidth - 左右 border`）
- **建议**：改为 `clientWidth == 96`；并补 `padding:3px` 用例说明「padding-box 含 padding、不含 border」
  与 `content-box` 的区分（防再算错）。

### B5（P0）Shadow 作用域隔离的「查询面」在活跃路径上不存在
- **问题**：§3.5 把「`document.querySelector('#x')` 为空」当作 Shadow 隔离的**判别力核心**（`:552`），
  §1.5 落点写「`web-dom` 查询面」（`:430`）。但：
  - 现网 JS shim **没有** `querySelector`（只有 `getElementById`/`createElement`/`appendChild`）；
  - `web_dom::collection::LiveCollection` 与 `web_dom::Document` **未被 navigation 使用**
    （页面路径直接用 `Rc<RefCell<NodeTree>>`），把它们当「查询面」是建在死路上；
  - 同理 `host.attachShadow(...)`、`element.shadowRoot`（§1.2/§1.5/时序图第五节）在 shim 中**均不存在**。
- **证据**：`binding.rs:551-667`（SHIM 全文，无 querySelector/attachShadow/shadowRoot）；
  `grep -rn "querySelector|attachShadow|shadowRoot" crates/` → **0 命中**；
  `page.rs:251/254`（`NodeTree::with_generation_base` 直接建树）、`:529-537`（`BindingInputs` 只含
  tree/mutations/writes/registry/activation/active_element/parser_active）；
  `document.rs`/`collection.rs` 无 `navigation` 引用
- **建议**：
  1. 在 §1.1/§5 明确**新增** JS 原语与 shim：`__iv8_dom_query`(selector) + `document.querySelector`、
     `__iv8_dom_attach_shadow` + `host.attachShadow`、`shadowRoot`、`getComputedStyle(...).getPropertyValue`，
     并各配一条 S 步骤与验收测试（不能隐含在「web-dom 查询面」一句话里）。
  2. 或者：把 shadow 隔离的**探针（P-4）与单测**降到 **Rust 层**（用 stylo 匹配 API + `NodeTree`
     作用域遍历断言「light 遍历不含 shadow 节点」），把 JS 层 `querySelector` 隔离留作**集成测试**。
  3. 明确 Shadow 的轻/影遍历：`flattened_children` 与「light 查询」必须是**两个不同的遍历**，
     这需要一个**限定作用域的查询 API**（现在没有）。

### B6（P0）UA 默认样式表来源未定义
- **问题**：没有 UA 表就没有 `div{display:block}`、`body{margin:8px}` 等真实布局前提，几何真值
  （§3.2）会系统性偏。施工图只在时序图里出现一个 `ua_css` 形参（`:22`），**文件清单没有它的来源与内容**，
  也没有对应测试。
- **证据**：施工图 `:22`；文件清单 `:128-156`（无 UA CSS 资源）；§3.1 无 UA 表内容测试
- **建议**：把「内嵌 UA 样式表」（如 `include_str!("ua.css")`）列为 layout-backend 交付物，
  并加测试 `ua_default_display_block`（`<div>` 默认 `display:block` ⇒ 宽度撑满容器）。

### B7（P0）P-5 / U-9 的「与 Chromium 一致」判据**当前不可执行**
- **问题**：P-5 判据是「T1.3 差分 harness 比 offsetWidth/clientWidth/rect，逐属性对齐」（`:690`），
  §6 R11(c) 也以 Chromium 为外部真值。但仓库的差分 harness 只有 `NullDifferentialBackend`
  （**不接触任何浏览器**，`:127-142`），**无 CDP/真实 Chromium 后端**（全仓 grep `cdp` 0 命中）。
  即：G3 无法执行「与浏览器一致」的判定，却又把它写成验收判据。
- **证据**：`contracts/iv8_contract/differential.py:127-142`（`NullDifferentialBackend.evaluate` 显式抛错）、
  `:248-262`（`run_empty_manifest_harness` 用 null 后端）；`contracts/cases/` 仅 README（空清单）；
  施工图 `:674,:690,:658`
- **建议**：二选一 —— (a) 把「真实 Chromium/CDP 差分」**单列为 G3 一步**（成本大，触 §16/G4）；
  (b) **把 P-5 降级**为「内部数字自洽 + 手算自证 + 具名偏差登记」，把 Chromium 对比推 G4，并在 §6 R11
  里把「推迟像素级差分」写成**默认分支**而非「若对不齐」的兜底。

### B8（P1）失效模型：无「变更→脏级」映射 + `dirty_nodes` 疑似死字段 + 「按需」未定义
- **问题**：三处不闭合：
  1. `Invalidation { dirty_nodes: DirtySet, style_dirty: bool, layout_dirty: bool }`（`:286`）中，
     `mark_style(node)`/`mark_layout(node)` 收 `node` 却只置**全局 bool** ⇒ `dirty_nodes` 无消费点（死字段）。
  2. 没有任何地方定义「哪些 DOM 变更 ⇒ style 级 / layout 级」；S9 的 `relayout_if_dirty`（`:388`）缺驱动源。
  3. 「按需 resolve / 重算受影响子树」（`:216,:470`）没有 restyle-root 计算；§2.2 实为「若 `style_dirty`
     ⇒ 跑级联」，即**全树**。若 as-built 是全树，应**显名登记**（ADR-0017 as-built 范式）。
- **证据**：施工图 `:216,:285-292,:464-468,:470,:533`；`binding.rs:120-127`（mutation 记录点，只有
  `child_list`）；`MutationRecord`→dirty 无映射
- **建议**：补一张**变更→脏级表**（`class/style/attr` ⇒ style；含尺寸属性 ⇒ style+layout；
  `append/remove` ⇒ style+layout；`set_viewport` ⇒ layout 全量），并让 `relayout_if_dirty` 读
  `MutationBuffer`；`dirty_nodes` 要么用于 restyle root、要么删除。

### B9（P1）S4/S5/S7 的「≤400 行/步」不现实
- **问题**：`layout-backend/src/stylo_host.rs` 要**凭空实现 stylo 的 DOM trait 全套**（`TDocument/TNode/
  TElement/TShadowRoot/ElementContext` + `selectors::Element`），其规模可参照上游：`stylo_taffy`
  的 `convert.rs` 867 行 + `wrapper.rs` 569 行**仅是 stylo→taffy 的转换**。S5 的 `box_tree`（匿名盒+内联
  +Taffy 建树）叠 `text`（Parley 整形 + fontique 回退）也远超 400 行。S7 的 shadow 作用域同理。
- **证据**：施工图 `:624-627`；上游规模 `stylo_taffy-0.3.0-beta.2/src/{convert.rs(867),wrapper.rs(569)}`；
  `AGENTS.md` 铁律 3（diff ≤400 行）
- **建议**：S4 拆 `stylo_host`（trait 面）/`style_system`；S5 拆 `box_tree` 与 `text`；S7 拆
  「作用域匹配」与「slot→布局接线」。**拆步成本 < 一轮超限返工。**

### B10（P1）字体跨机确定性判据过严（P-10「逐字节相等」）
- **问题**：本地是 **arm64（M 系）**、远程是 **x86_64 Linux**。整形度量是 `f32`，跨架构在
  浮点收缩/FMA/向量化上**不保证逐位相等**。「逐字节相等」可能产生**假红**，反而掩盖真实的字体差异。
- **证据**：施工图 `:695`（P-10）；`:558-564`（§3.6）；`HANDOFF-2026-10-13.md:45`（macOS 本地 vs Linux 远程）
- **建议**：P-10 改为「同架构内逐位相等；跨架构 ≤0.5px 容差 + 记录 arch/字体哈希」；几何断言
  （`:562`）同步用容差而非「同断言值」。

## ⑤ 未决与留白

1. **技术方案 docx 缺席**：§18 原文、§7 docx:189、§8 的 C13/C14 原文均**不在仓库**。我按二手引文评审；
   若 §18 对「完整尺寸」「CSSOM 广度」的边界与施工图理解不同，结论需重估。
2. **`LayoutBackend` 的 G4+ 稳定性**：我倾向「**基本稳定**」（`resolve(now)` 已为动画留位，
   滚动/命中测试可**加方法**而不破坏 trait；`NodeGeometry` 加字段是内部小 break）。但两处会**被迫改签名**：
   `computed_value` 无 `pseudo`（D13）、`add_stylesheet` 无 `remove`（B11）。建议现在就补，避免 C14 破功。
3. **shadow 边界的 G3/G4 切分**：我**同意**「事件 retargeting/`composedPath`/`slotchange` 推 G4」
   （`:435`），但前提是 `flattened_children` + `ElementData.shadow` + `NodeKind::ShadowRoot` 能为
   retargeting 提供足够信息。当前设计**未给出** retargeting 所需的「composed path 回溯」接口，
   留白（低危，G4 再补）。
4. **D4（timer 事件循环）归属**：我**保留**。brief 推荐「timer + watchdog 归 G3」（`residual-scheduling.md:130`），
   但 timer 触**铁律 6**（scheduler 高风险）且**与「布局复用验证」主题弱耦合**；而 watchdog（U-12，
   安全缺口）应**无条件优先**。建议：**watchdog 归 G3（P0），timer 推 G4（除非某条失效测试非 timer 不可）**。
   施工图已把两者绑在 S12「视 D4」（`:632`），建议**拆开**。
5. **`R11` 切换判据里的 `FONT_DETERMINISTIC`**：若按 B10 改容差，「确定」的定义要同步改，
   否则判据悬空。
6. **范围一致性**：施工图 §0.2 把「CSSOM 长成」纳入 G3，而 `HANDOFF:68` 说「通过后开展 DOM/CSSOM/API
   广度扩展」（即 CSSOM 广度似在 G2 之后、G3 之内）。二者不冲突但需在 ADR 里写清「G3 的 CSSOM =
   计算值投影最小面，非广度扩张」，避免 R7 式过度承诺（`:654`）。
