## §1 🟠 F22：`storage` 事件面**无分母载体**（「`S0` 时少种」第四例）

- **设计明文**：设计 v3 冻结文 §9 表第 9 族 = 「**`storage` 事件（跨文档）｜进分母（`4.1s`）｜`M1`**」。
- **实物**：`contracts/community-v0.1.4-members.json`（1698 条）中 **`StorageEvent.*` / `onstorage` = 0 条**（webref 接口自名单未含 `StorageEvent`；`Window` 接口整体亦不在分母）。
- **后果**：S1c 的行为证据（6 测）**无法流转进 manifest** —— 无 id 可 `promote`；`4.1s` 的「撤事件派发 ⇒ 红」判据目前只有 Rust 侧证据，**manifest 侧无承接条目** ⇒ `S6` 出口核对时该面呈「清单里没有」而非「已 verified」。
- **与既有族关系**：同 `F3`（联合类型漏列）/ `D-S2-1`（Credentials 0 条）—— **`S0` 时少种**；`4.0` 只防事后删、不防封口时少种（评审员 B 预警的实证延续）。
- **待裁（`D-S1c-1`，不代为执行）**：
  1. **补**：`StorageEvent` 接口成员进分母（自然集 = `key`/`oldValue`/`newValue`/`url`/`storageArea`；设计 4.1s 判据载 key/old/new/**url** 四字段）⇒ **须新 ADR**（分母刚经 ADR-0028 变更，禁顺手补）；补后 S1c 的 test_ids 方可真实化流转；
  2. **或具名移出**：若裁「事件面不走成员级分母、证据由 Rust 测承担」⇒ 须 **ADR 显名**（设计 §9 表收口条：移出须 ADR），且 `4.1s` 出口判据口径随之改写。
- **附带（补时一并裁）**：实现面 `StorageEvent` 字段为 `origin/kind/key/old_value/new_value`，与设计 4.1s 的 `key/old/new/**url**` **不完全对齐**（缺 `url`，多 `origin/kind`）—— pull 模型下 `url` 可由宿主派生，但**入分母前须裁定字段集**，不得以实现倒推契约。

## §2 具名登记核对（`S1` 风险裁定 ①）

- 台账 §1 `S1` 风险裁定 ① 原裁：「`4.1s` = 优先测试内双上下文（同 origin），不可行 ⇒ 具名登记（"自文档不触发"负证 + `cross-delivery` 延后）」。
- 本笔落地形态 = **pull 模型**（无监听器注册面）⇒ 「自文档不触发」为**结构性保证**（优于负证：无需构造"不应触发"的观测）；**跨文档派发具名延后**已在 `crates/navigation/src/page.rs` `take_storage_events` 文档注 + 本核可落账 ⇒ **登记在位，非静默丢域**。
