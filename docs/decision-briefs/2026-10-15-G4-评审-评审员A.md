# 真 G4 设计批 · 独立评审 A（**证伪视角**）—— 2026-10-15

> 只读仓内 + **直接抽取 docx 原文核验**（`python3 zipfile` 提取 `word/document.xml`）＋ `manifest.py` / ADR-0025 / G3X 尾账；不改码。

**结论：有条件支持。** §18 回引与术语止血成立（我独立核验 docx：`G4 平台能力闭环 = 存储、密码、连接 fixture、图形与媒体契约、宿主 CDP 域；通过后 清零社区版 missing/unknown` ✓）。**但 `level` 是"自证字段"、schema 与章程字段集不符、出口口径与既有 `BLOCKING_STATUSES` 未对账、M0/M5 严重低估、矩阵 2 条负对照不可执行。** 建议**先修 5 项必改再冻结**。

## ① `level` 会不会变成打折借口？——**会，现在就是**

- **无判定规则、无负对照 ⇒ 自证字段**：§6 只要求"逐条记录"，§8-5/R7 只要求"面级不得呈现为全量"，**没有任何机器判据**（谁判定、依何证据、错标如何变红均未定义）。按静默家族问句——把行为级错标为面级，**观测量不变** ⇒ **空门禁**。**必改 1**：`level` 须**由证据类型派生**（行为级须附状态转移表/时序钉值；面级禁止附行为证据）+ **负对照「错标 ⇒ 红」**。
- **schema 与章程不符（硬伤）**：docx 原文：条目"至少包括 `target_version`、`interface/member`、`realm`、`descriptor`、`behavior_level`、`test_ids`、`status`、`evidence`、`implementation_owner`"。设计 §6 = `{id, source, behaviour, level, runner, mode, evidence}` ⇒ **缺 `target_version`/`realm`/`descriptor`/`test_ids`/`implementation_owner`**，且把章程单一 `behavior_level` 拆成 `behaviour`+`level`（**语义重叠、歧义**）。**必改 2**：schema 对齐章程；**`test_ids` 缺失直接打断「逐条目证据可追」**（`evidence` 是自由文本，无法机器校验）；**`implementation_owner` 缺失 ⇒ 无人负责**。
- **出口口径未对账**：`manifest.py:67-69` `BLOCKING_STATUSES = {FAILED, MISSING, UNKNOWN}`、`is_release_blocking()`；docx 亦写"**后三者不能进入社区版等价发布**"。设计 §出口/§6/§4.6 只清 `missing/unknown` ⇒ **同仓两套"阻断"定义**。**必改 3**：显式声明「G4 出口 = `missing/unknown==0`；`failed` 非零须逐条具名理由 + 白名单」。
- **分母只防"删"、不防"起点选小"（根缺口）**：§6.1 自承「§18 接口清单**无机读产物**」「**G0 冻结清单全仓不存在**」⇒ **分母完整性无上游真值**；`denominator_fixed`/`4.0` 只测删除、不测**漏列** ⇒ "清零"可由**少列条目**达成而观测量不变 = **静默家族第 1 型**。**必改 4**：须有**完备性判据**（§18 清单机读提取 + 社区版 `v0.1.4` 实测双模式对照）并单列验收行。另：`denominator_fixed:true` 与「清单 S0/S1 才填充」**语义冲突** ⇒ 须定义「**冻结时点 = S0 结束**」，`4.0` 须同时测「新增/替换须显式升版」。

## ② 验收矩阵 11 行判别力（「失败时观测量会不会变？」）

- **不可执行（2 条，阻断级）**：`4.2b crypto_primitive_stub_only` 负对照「真原语被实现而未上报 ⇒ 红」——若桩与真实现**签名相同**则**无法区分** ⇒ 恒绿。**改判据**为「`crypto.subtle` 全部方法返回显式 stub 错误（`NotSupportedError`）」⇒ 真实现必破坏该断言。`4.0`「分母恒定」若无**独立基线**则退化为**自证**（读文件自身）⇒ 须引外部 golden + 铁律 2 独立 PR。
- **弱**：`4.1` 未给**配额数值与超出行为**（须钉「第 N+1 次写抛 `QuotaExceededError`」）；`4.1b`「重载后值仍在」**取决于"重载"是否换存储实例**（同进程静态 map ⇒ "仅内存"也过）；`4.1c`「objectStore 基本语义」**未给操作序列**（须钉 `open→onupgradeneeded→createObjectStore→add→onsuccess`）；`4.3`「无网络仍可跑」须钉**固定 fixture 字节 + 状态码**；`4.4`/`4.4b`「契约存在」实为**编译期**（删 trait ⇒ 编译失败），**非运行期门禁**。
- **中**：`4.2` 行为级**状态转移表 + 两条可判别负对照 = 全表最强** ✓（但"应拒"须钉**返回错误类型**）；`4.3b` 须钉**具体事件序列**（`open→message×2→close` + 逻辑时间戳）；`4.5` 见 ⑤。
- **共性缺口（必改 5）**：11 行负对照几乎都是"撤 X ⇒ 红"= **人工注入（INJ）**，而设计**未定义谁执行/何时执行/是否入 CI/是否留档** ⇒ 不执行则整体退化为自证。须制度化「负对照 = **INJ 用例 + 留档**」。

## ③ M0~M5 低估 / 章程冲突

- **M0 = 最大的一步**（非"基线填充"）：须从**空**建到章程 9 字段完整清单，且 §18 清单**须先提取机读化**（R8 可能触发）⇒ **阻塞 S1~S5 全部**。**拆 M0a（docx 提取机读化）/ M0b（分母冻结时点）/ M0c（schema+负对照）**，并给 R8 触发的**停滞时间盒**（现仅给退路，无预案）。
- **M5 = 从零实现 CDP 服务端子集**（握手 + 命令/事件 + 会话 + 序列化），一步 P0 **严重低估**；且子集**循环依赖**（见 ⑤）。
- **M3 与章程冲突面**：docx 明写「社区版等价要求核对其真实行为，**不能自行把未知功能降级为 NullProvider**」⇒ G4 须**逐条显名**「fixture 层 = 面级达成；真实传输 = G6」；否则记 `verified` 违规、记 `missing` 违"清零" ⇒ **须把该禁令写进 M3 验收**。WT fixture 仅接口+Null，真语义 ⇒ G6（具名）。
- **M2 语义归属**：`4.2b` 把 **`crypto.subtle` 归入「密码」M2**——crypto 属 Web Crypto API、非 Credential Management，**跨面借用须具名**。## ④ §9 风险不够（R1~R8 实为 8 条）——补 R9~R15

**R9 清单不完备/分母起点可选小（最根本，R1 只防删）｜R10 `failed` 非零可过出口｜R11 负对照不执行 ⇒ 纸面门禁｜R12 字体跨机口径（G3 R4 在真 G4 无对应条目）｜R13 M0 阻塞链（docx 不可提取 ⇒ 全 G4 停摆，缺时间盒）｜R14 M5 子集与 G5 差分（无早验 ⇒ G5 返工）｜R15 `level` 与章程 `behavior_level` 对齐。**
另：**R3 只覆盖 M3**，但 **M1（IDB 事务）/M2（状态机）/M5（CDP 会话）同样有时序不确定性** ⇒ 应泛化。

## ⑤ §7 裁定可挑战处

- **7-4(b)**：站得住，但**"行为级别三态（`stub`/`contract`/`behaviour`）"与 manifest `level` 二值（面级/行为级）不一一对应** ⇒ **两套级别体系并存且矛盾**（R2 三态 vs §6 二值）。**须统一**。
- **7-5(b)**：**循环依赖**——"子集以 manifest 为准"，而 manifest 待 S0 填充 ⇒ **M5 域子集清单须在 S0 先行冻结**。
- **7-6(b)**：§6.1 已实测"G0 冻结清单**不存在**"并给修订建议，但 **§7 表格仍写 (b)** ⇒ **文本未收敛（自相矛盾）**；修订须落 ADR/正文。
- **7-3(b)/M3**：见 ③ 章程禁令。**7-1(b)**：站得住，但"基本语义"**未定义边界** ⇒ 补**面级操作清单**（否则 R4 无法机器防蔓延）。**7-7(d) / 7-8(b) / 7-2(b) 契约层级**：**同意** ✓。

**⑥ 文档一致性（必改）**：头部「**状态：定稿 v2**（§7 八项已裁）」与尾部「本稿 = **全文草案**；**§7 待裁 8 项** 待主理人逐项裁」**直接矛盾**；§3/§4 标题仍标"（拟）"⇒ 须收敛。

> **必改项（落档前）**：① `level` 判据+负对照｜② schema 对齐章程 9 字段（尤 `test_ids`/`implementation_owner`/`behavior_level`）｜③ 出口与 `BLOCKING_STATUSES` 对账（`failed` 口径）｜④ 清单完备性判据（防"起点选小"）｜⑤ 负对照 INJ 制度化。**另**：M0/M5 拆分与低估修正、R9~R15 补、7-4/7-5/7-6 收敛、文档状态矛盾。
