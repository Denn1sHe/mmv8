> **as-built 复核（HEAD `0b55f30`）**：§1 由 `0b55f30`（R19 判别性观测）回归、§2 由 `fcd77f4`（§3.1 六条全绿）落地 ⇒ 本稿兼作**正确序列的源级依据 + 残余风险登记**。

## §1 结论（样式表移除后重算）

**已实现的序列正确且充分；「移除后重算仍旧值」几乎确定是 `display` 观测值无判别力，而非 stylo 重建缺口。**
`Display(514)` == `Display::Block`；内嵌 UA 表自身就 `div { display: block; }` ⇒ 该观测**测不出**移除是否生效（对照组用 `width` 故能测出，差异在观测值选择）。

**正确序列（源码依据）**
1. `Stylist::append_stylesheet`（`stylist.rs:1117`）→ `SheetCollection::append` 置 `dirty`（`stylesheet_set.rs:258-267`）。
2. `Stylist::flush`（`stylist.rs:1055-1078`）：`has_changed()`（`stylesheet_set.rs:495-501`）→ `DocumentCascadeData::rebuild`（`:503-557`）→ `CascadeData::rebuild`（`:3456-3511`）。
3. `Stylist::remove_stylesheet`（`stylist.rs:1124`）→ `DocumentStylesheetSet::remove_stylesheet`（`stylesheet_set.rs:380-392`）→ `SheetCollection::remove`（`:232-251`）：`find_sheet_index` 按 **`Arc::ptr_eq`**（`stylesheet.rs:291-295`）⇒ 必须传同一 `Arc<Stylesheet>`；命中且 `committed` ⇒ `set_data_validity_at_least(FullyInvalid)`（`:282-289`）。
4. flush 内 `validity != Valid` ⇒ **`clear_cascade_data()`**（`stylist.rs:3474-3479`；体 `:4689-4715` 清空 `normal_rules`）⇒ 移除表的规则消失；随后只重加现存 entries（`:3484-3500`）。
5. 解析前保证元素无陈旧数据：`clear_data()`（`stylo_host/mod.rs:207-209`）或每次重建槽。

**答疑**：① **次序不敏感**；`force_stylesheet_origins_dirty`（`stylist.rs:1085`）对移除是**冗余**的（`remove` 已置 FullyInvalid），保留无害。② **不需要额外 API**——stylo 0.20 **无** `set_stylesheets`（仅 append/insert_before/remove/rule_changed），`flush` 是唯一必需触发点。③ `flush()` 返回的 `StylesheetInvalidationSet` 被丢弃（`style_system.rs:168`）：在「`clear_data` + 全量重算」下无害；改增量失效则**必须应用**。

**决定性判据**：`assets/ua.css:11` = `div { display: block; }`；`Display(u16)` 位布局 `LOOOOOOOOIIIIIIII`（`values/specified/box.rs:173-177`），`DisplayOutside::Block=2`、`DisplayInside::Flow=2`（`:88-105`）⇒ `Display::Block=(2<<8)|2=`**514**，**精确等于工程师读数** ⇒ 514 正是「移除成功后应得的值」。

**修复建议（已按此回归）**：① 观测换 `width`（作者 `#box{width:120px}` → 移除后回 `auto`）；② 机器诊断 `sheet_count(Origin::Author)` 1→0（`stylist.rs:1153`）+ `num_rebuilds()` 递增（`:1023`）；③ 负对照：保留 UA 表、断言 `display` **保持** block；④ 断言不 panic——servo 下未命中会 `index.unwrap()` panic（`stylesheet_set.rs:234-238`），无 panic 即证同一 `Arc` 命中。

**残余风险（登记）**：`resolve_element_style` 仅对**被解析元素** `clear_data`（`style_system.rs:193`）；多元素/整页需逐个清或应用 `flush` 返回的失效集，否则**其它元素**呈旧值。

## §2 结论（`inline_style_wins_over_author`：`style_attribute` ⇄ `guards` 配对）

**必须用「同一把」锁，canonical 实例 = stylo 自有的 `GLOBAL_STYLE_DATA.shared_lock`。** as-built（`fcd77f4`）已绿，但其配对是**自洽的第二把锁**，与 `TDocument::shared_lock()` **并非同一实例** ⇒ 存在**潜在错配**（见 §2.4）。

**§2.1 锁身份语义**：① `SharedRwLock { cell: Option<Arc<AtomicRefCell<ZST>>> }`，`#[derive(Clone)]`（`shared_lock.rs:27-30`）⇒ **`.clone()` 共享同一 `Arc`**（身份保持）；`new()`/`new_leaked()` 各造**新身份**；`read_only()` ⇒ `cell=None`（`:46-64`）。② `Locked::wrap` 把**当时的锁**存进块内（`:75-80`）⇒ **身份在 wrap 时定格**。③ `read_with` 断言 `is_read_only_lock() || same_lock_as(guard.ptr())`（`:138-144`），`same_lock_as = ptr::eq(self.shared_lock.ptr(), guard.ptr())`（`:133-135`）⇒ 文案「guard from an **unrelated** SharedRwLock」字面即**两个锁实例**。④ `read_only()` 令断言**短路**，但 `write_with` **显式拒绝**（`:165-168`），in-tree 唯一用途是 **shmem**（`:184-195`）⇒ 非动态 style 属性正解；**若把「锁」而非「块」设 read_only**，会得到 `ptr()==null` 的 guard 去读普通块 ⇒ **必然断言失败**（这解释了「试 `read_only` 仍不匹配」）。

**§2.2 谁在读、用哪把 guard**：① style attribute 以 `CascadeLevel::same_tree_author_normal()` 入规则集（`rule_collector.rs:478-487`），读取点按 origin 选 guard ⇒ **`guards.author`**（`rule_tree/mod.rs:81` `source.read(level.guard(guards))`；`properties/cascade.rs:154-156`；`StylesheetGuards::for_origin` `shared_lock.rs:249-254`）。② stylo 自身 wrap 声明块的惯例 = **`document.shared_lock()`**（`servo/animation.rs:236`，随后即用 `&context.guards` 读）；**参考实现** gecko 的 `TDocument::shared_lock()` 返回 `&GLOBAL_STYLE_DATA.shared_lock`（`gecko/wrapper.rs:138-139`），该锁即 `GlobalStyleData{ shared_lock: SharedRwLock::new_leaked() }`（`global_style_data.rs:44-46`/`:221-222`）。③ 同源路径还有 `matching.rs:567`（`owner_doc().shared_lock()` 取动画声明）——本仓 `DocumentAnimationSet::default()` 为空，当前不触发。

**§2.3 正确序列（standalone）**：① 单锁来源 `&style::global_style_data::GLOBAL_STYLE_DATA.shared_lock`（= `TDocument::shared_lock()`；本仓 `stylo_host/dom.rs:57-58` 已如此）；② **用它 wrap**：样式表 media（`style_system.rs:112`）与 **style attribute 块**（`stylo_host/mod.rs:294` `lock.wrap(block)`）；③ **用它取 guard**：`lock.read()` → `StylesheetGuards::same(&guard)`（`style_system.rs:198-199`）；④ `build_slots(&tree, lock)` 传**同一把**（调用点 `style_system.rs:269/301/…`）。

**§2.4 ⚠️ 潜在错配（最高危，建议纳入批准包）**：本仓现存**两把**进程级锁——`stylo_host::global_shared_lock()`（自建 `new_leaked()`，`mod.rs:33-36`）**≠** `TDocument::shared_lock()` 的 `GLOBAL_STYLE_DATA.shared_lock`（`dom.rs:57-58`）。现状能绿，仅因 style attribute 的 **wrap 与 guard 同取自那把自建锁**（`style_system.rs:76→112/198`；`shared_lock()` 返回 `&self.lock`，`:173-175`）⇒ 自洽，而 `document.shared_lock()` 路径（动画）当前为空。**一旦接入动画 / `rAF`（`servo/animation.rs:236`）或任何经 `owner_doc().shared_lock()` 的读写，即命中 `read_with` 断言。**
**建议（零行为变化）**：令 `global_shared_lock()` 直接返回 `&GLOBAL_STYLE_DATA.shared_lock`（或删除，统一走 `TDocument::shared_lock()`），把「一把锁」由**构造**保证，消除该断言面。**不建议**以 `read_only()` 规避（shmem 专用、永久只读）。

### §2 附记：R20 实测自解（`fcd77f4`）+ 确认性复核（评审员 A）

- **R20 解**：`Locked` 与 `StylesheetGuards` 必须同源 ⇒ `build_slots(tree, system.shared_lock())` 传**同一 `SharedRwLock` 实例**（本仓 `style_system.rs:76/112/173-175/198` 即此形态）。前三次尝试失败皆因**非同一实例**。
- **① 完整性（同源）**：本仓全部 `Locked` 数据（样式表 media `:112`、style attribute `stylo_host/mod.rs:294`）与全部 guards（`add_stylesheet :126`、`flush :167`、`remove :147`、`resolve :198`）**均取自 `&self.lock`** ⇒ 自洽无缺口。
- **② 唯一异源**：stylo 内仅 3 处以**文档锁**读写——`matching.rs:567`、`matching.rs:650`、`servo/animation.rs:236/1694/1700`；均属动画路径，且 `get_all_declarations` 在空集时**提前返回**（`animation.rs:1687-1690` Default）⇒ 本仓 `DocumentAnimationSet::default()` 下**不触发**。**故当前无实害，但属登记隐患**（§2.4）。
- **③ 生命周期**：`self.lock` 为 `StyleSystem` 字段，源自 `SharedRwLock::new_leaked()`（`Arc::new_leaked` ⇒ 进程级分配，`shared_lock.rs:53-59`）；`wrap` 存锁的**克隆（共享 Arc）** ⇒ 泄漏的 `ElementSlot` 持其 Locked 始终有效；多个 `StyleSystem` 实例**共享同一身份**（皆克隆同一静态）⇒ 跨实例一致。
- **④ rebuild 后身份保持**：`clear_cascade_data`/`CascadeData::rebuild` 不触及锁身份；重建仅从**同一 `Arc<Stylesheet>`** 重加规则（同一 Locked）⇒ flush/rebuild 前后身份**不变**。
- **复核结论：无新隐患**；唯一登记项 = §2.4 的**双锁**（动画接入前须统一为 `GLOBAL_STYLE_DATA.shared_lock`）。
