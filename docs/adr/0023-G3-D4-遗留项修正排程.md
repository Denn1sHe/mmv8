## 问题

G2 留了四个「已登记、非缺陷」的残留项：① 脚本任务化（U-10-a）、② timer 事件循环（U-10-b）、
③ 模块 watchdog 缺口（U-12）、④ 宿主驱动路径 `try_borrow` 残余（D4）。G3 以布局为核心——
**哪些挪进 G3、哪些推 G4**。

## 讨论要点

| 维度 | 评审 A | 评审 B | 主理人裁决 |
|---|---|---|---|
| 失效测试能否同步完成 | **能**（施工图 §3.3 四条全同步 + 显式 `resolve`）⇒ 应落方案 A | 同 | **采纳** |
| brief 推荐自相矛盾 | **指出**：推荐方案 B，但设计自身已证 U-1/U-4 成立 | 同 | **采纳** |
| timer | 触**铁律 6**（scheduler 高风险）⇒ 若做须单列 ADR | 与布局弱耦合 ⇒ 推 G4 | **采纳：→ G4** |
| 模块 watchdog（U-12） | 安全缺口，建议**单列 P0** | 应**无条件优先** | **采纳：→ G3 独立 P0 小步** |
| 脚本任务化 / 宿主 try_borrow | 推 G4 | 与布局无耦合 | **采纳：→ G4** |

## 决策

### 决策 1 —— **timer 事件循环 → G4**

依据：施工图 §3.3 的**四条失效测试全部可用「同步脚本 + 显式 `resolve`」完成**（两评一致已证）
⇒ 按 brief §2 子问题 1 的判据，U-1/U-4 成立 ⇒ timer **非 G3 必需**。且 timer 触**铁律 6**
（scheduler 事件循环 / 时序），若确要做**必须单列 ADR**。

### 决策 2 —— **脚本任务化 + 宿主 `try_borrow` → G4**

依据：与布局**无直接耦合**（G2 已用同步脚本覆盖）；宿主 `try_borrow` 残余已被 ADR-0016「QA-R1·D4」
裁定「非 V8 回调边界、冲突面小」，G3 的 `resolve` 同性质 ⇒ **风险不因 G3 放大**。

### 决策 3 —— **模块 watchdog（U-12）→ 抽出为 G3 内独立 P0 小步**

依据：**安全缺口**（模块内死循环不受 2 s 截断），与布局因果上**可解耦**；不应被塞进「视 D4 裁决」
的 P1/P2 里顺延。**验收测试**：`module_deadloop_terminates`（模块死循环 ⇒ 稳定 `Terminated`）。
**S12 中 watchdog 与 timer 的绑定结构拆开**：watchdog 独立成步（施工图 **S14**），timer 移出。

### 决策 4 —— 施工图步骤结构拆开

- 原「S12（视 D4）：timer 事件循环 + 模块 watchdog」**拆**为：
  - **S14 模块 watchdog（U-12）** = 独立 **P0**（G3 内）；
  - timer 事件循环 **移出** G3（G4）。
- 脚本任务化 / 宿主 `try_borrow` **移出** G3（G4）。

## 后果

### 正面
- G3 聚焦「布局复用验证」；安全缺口（watchdog）**不被顺延**；timer 的高风险（铁律 6）不进 G3。

### 代价（如实登记）
- 执行模型（脚本任务化 / timer）G3 仍为 as-built 状态（登记延续），G4 收口。

## 遗留（本 ADR 不做 → G4）
- 脚本任务化（U-10-a）；
- timer 驱动页面事件循环（U-10-b）；
- 宿主驱动路径 `try_borrow` 残余（ADR-0016·D4）。
