## 问题

G2 的「输入」做到哪一层，以及三个机制缺口：① JS 侧 `Event` 对象桥；② 分派期监听器变更语义；
③ `el.click()` 与 ADR-0014 重入禁令的冲突。两评审均**同意方案 A（显式 target 可信事件、命中测试推 G3）**
（与几何 stub 口径自洽、不做=不假绿）；但指出分派语义有 3 破坏点 + 1 安全窗口、JS `Event` 桥缺失。

## 决策

### 决策 1 —— JS `Event` 对象桥（B-断链 9；阻断→补齐）

`web-events::Event` 是纯 Rust struct；JS 监听器需读 `event.isTrusted`/`currentTarget`/`type` 等 ⇒ 必须构造 **JS 对象**。
定稿（由 `navigation::input` 经 `engine_v8::Realm::new_object`/`set_prop`/`get_prop` 实现）：
- **构造**：每个事件建一个 JS 对象（存 `type`/`bubbles`/`cancelable`/`isTrusted`/`timeStamp`）；
- **逐 step 更新 `currentTarget`**（进入每个 `DispatchStep` 时 `set_prop`，`phase` 同步）；
- **回读**：`preventDefault`/`stopPropagation` 由桥接 native fn 回写 Rust `Event.default_prevented`/`propagation_stopped`；
- 交付后事件对象不保留强引用。
⇒ 使 `trusted_click_dispatches_to_target`、`untrusted_event_not_trusted` **可写**。

### 决策 2 —— 分派期监听器变更语义（A-§4.2；快照不足）

`plan_dispatch` 不再以「值拷贝 = 快照」为终态；定稿：
- `DispatchStep.listeners` 存**稳定注册 id（u64）+ callback/options**；
- **调用前向注册表查活性**：`once` 触发后 与 `removeEventListener` 共用「**移除即置 dead**」路径；
- **移除尚未调用的监听器 ⇒ 调用时跳过**（规范要求）；
- **同 target 分派期间新增 ⇒ 不参与本次**。
- 测试：`listener_removed_during_dispatch_not_invoked`、`listener_added_during_dispatch_not_invoked`。
（并且 `plan_dispatch` 结果仍是 **owned `Vec`**，借用在任何 `call` 前释放——ADR-0016 决策 2 / B-断链 10 序列②。）

### 决策 3 —— 注册/移除匹配与去重（A-§4.3）

- `add(target, type, callback, capture, opts)`：**已存在同 `(type, callback, capture)` ⇒ no-op**（不重复添加）。
- `remove(target, type, callback, capture)`：**只按 `(type, callback, capture)` 匹配**（忽略 `passive`/`once`）。
- 测试：`duplicate_add_is_noop`、`remove_ignores_passive_once`。

### 决策 4 —— at-target 调用顺序**登记 + 规范锚定**（A-§4.4，U-A）

`plan_dispatch` 生成 `capture → at-target(capture) → at-target(bubble) → bubble`；但规范里 **target 上两类监听器
按注册顺序混合调用、`eventPhase` 取 AT_TARGET**。定稿：**以固定修订版 DOM Standard / WPT 子集锚定**
（本机无副本、本轮不联网 ⇒ 登记 **U-A**）；加契约测试 `listener_order_at_target_mixed_registration`。
（S3 实现按现模型，测试作为锚定判据。）

### 决策 5 —— `resolve_weak`/`call` 安全窗口 ⇒ **`call_weak` 原子入口**（A-§4.5）

`resolve_weak` 返回的 `HostValue::Function{handle}` 仍是**弱槽下标**，`call` 时再次 `resolve` ⇒ 两步间存在**回收窗口**
（当前编排两步间无分配 ⇒ 实际安全，但属「不许分配」纪律）。结构消除：
**`engine-v8` 增 `call_weak(w: WeakJsHandle, this, args)`（解析 + 调用原子）**；**监听器调用只走该原子入口**。
测试 `listener_collected_before_call_skipped`。

### 决策 6 —— `el.click()` 与重入禁令：**区分两种重入**（A/B 同判冲突的裁决）

`Realm::call` 在 `in_callback==true` 时报 `ReentrantEval`（`realm.rs:344-349`）⇒ **脚本内同步 dispatch 会被自己的重入禁令挡住**。
裁决：
> **区分两种重入**——① 「宿主回调内再次**求值脚本**（`eval`/`eval_module`）」**维持禁令**（ADR-0014 决策 3）；
> ② 「**分派期调用监听器**（`call`）」为**语义必需**，由**专用路径**放开（`engine-v8` 设计具体形态 + SAFETY/深度论证）。

- `engine-v8` 提供分派专用调用入口（与 `call` 分离，仅在事件分派编排内可用），带**深度论证**（重入仅限「同一次事件分派的监听器调用」这一有界形状）。
  **实现形态（批 2C 落盘）** = `call_impl` **同款裸指针形态**、**仅跳过 `in_callback` 禁令**；**无新增 `unsafe` 块**
  （复用既有 `#[allow(unsafe_code)]` 块）；论证随码。
- **ADR-0014 追加修正注记**：把「重入禁令」的适用范围精确化为「求值类入口」；分派调用走专用路径。
- 记录于本 ADR；形态由 S3/S12 定稿并附专测。

### 决策 7 —— `UserActivation` 最小口径 + `activeElement`（A-§4.6 / B 残余 #3）

- 技术方案 §7 docx:195 要求「更新 pointer、button、focus 和 user activation 状态」⇒ G2 只做 **`sticky`**，
  是**范围缩减** ⇒ **必须与几何 stub 同规格**：`capabilities.input="explicit_target"` + 明文档登记（不是假绿）。
- **`transient` 在 G2 无消费方** ⇒ **明确「G2 不置位、G3 再用」**（或删）——避免「有字段＝已实现」误读。
- **`activeElement` 最小态纳入**（`document.activeElement` 可观察）⇒ 使 `click ⇒ 聚焦` 的默认动作**有断言**。
- 默认动作最小状态机：click ⇒ 聚焦（并更新 `activeElement`）；不做表单提交/导航默认动作。

## 后果

### 正面
- JS `Event` 桥 + `call_weak` 原子入口 ⇒ §3.6 两条关键测试**由写不出变可写**；
- 监听器变更/注册语义**按规范定稿**（去重、移除生效、新增不生效）；
- `el.click()` 重入冲突**裁决闭合**（专用路径，具 SAFETY/深度论证）；
- `transient`/`activeElement` 口径清晰（不假绿）。

### 代价（如实登记）
- 事件分派编排需构造/维护 JS 事件对象（每 step 更新 `currentTarget`）；`engine-v8` 需新增「分派专用调用入口」
  （触铁律 6 评估，需 SAFETY/深度论证）。
- `UserActivation.transient` 名义存在但 G2 不置位（登记）。

### 待实测登记
| # | 待实测项 | 落点 |
|---|---|---|
| T7 | `call_weak` 原子性（无两步回收窗口） | S3/S12（`listener_collected_before_call_skipped`） |
| T8 | 分派期 remove/add 语义 | S12（`listener_removed_during_dispatch_not_invoked`/`..._added_...`） |
| U-A | at-target 混合注册序（规范锚定） | S3 契约测试（`listener_order_at_target_mixed_registration`） |

### 遗留（本 ADR 不做）
- pointer/button 状态与「统一默认动作状态机」（G3）。
- 命中测试（坐标→目标）（G3，依赖布局）。
