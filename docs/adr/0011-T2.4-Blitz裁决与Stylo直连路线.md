# ADR-0011：T2.4 裁决 —— Blitz 的动态 DOM 与样式失效成立，但 **Shadow DOM 未实现**，切换到 Stylo + Taffy + Parley 直连路线

- 状态：**已接受**（PoC 实测；裁决依据是 C9 的稳定实测结果）
- 日期：2026-10-12
- 关联：`docs/TASKS.md` 的 T2.4
- 探针源码：`poc/t2_4_blitz_probe/src/main.rs`
- 运行方式：`cd poc/t2_4_blitz_probe && cargo run --offline`
- 依赖：`blitz-dom = { version = "=0.3.0-beta.2", default-features = false }`、
  `blitz-traits = "=0.3.0-beta.2"`、`markup5ever = "0.39"`

---

## 问题

技术方案 T2.4 要回答：**Blitz 的动态 DOM、样式失效与 Shadow DOM 集成**走不走得通。

原始表述带一条明确的退出条件：

> Blitz 的动态 DOM、样式失效与 Shadow DOM 集成
> （**不通过则切直接 Stylo + Taffy + Parley**）

本 ADR 的产出是一次**路线裁决**：走 Blitz，还是切直连路线。
**裁决必须建立在实测上，不能靠「文档说它支持」或「文档说它不支持」。**

---

## 实测方法

### 关键设计 1：`default-features = false`（否则 C2 必失败）

`blitz-dom` 的 `[features]` 原文：

```toml
default = ["svg", "woff", "accessibility", "system-fonts", "file-input", "custom-widget"]
custom-widget = ["dep:anyrender", "accessibility"]
```

`default` 含 `custom-widget` ⇒ 拉入 `anyrender`（GUI 栈），**违反技术方案 §3**
「不整包依赖 GUI」。实测对比：

| 配置 | 锁定的包数 | GUI 栈 |
|---|---|---|
| 默认 features | 243 | **含 `anyrender`** ✗ |
| `default-features = false` | **191** | **无** ✓ |

> 注意：`blitz-traits` **没有** `[features]` 段，故对它写 `default-features = false`
> 无害也无意义，**统一不写**，避免误导以为做了实事。

### 关键设计 2：`StyleThreading::Sequential`（避开 rayon）

`StyleThreading` 默认是 `Parallel`，走**全局 rayon 线程池**，其文档明说
「panics if another `Parallel` resolve is in flight on a different thread」。
我们要的是单页面线程模型，故显式选 `Sequential`。

### 关键设计 3：C9 必须**真去尝试**，不能因源码写了 `todo!()` 就直接写 `false`

这是本探针最容易做成**恒假门禁**的地方。若直接写 `SHADOW_DOM_WORKS=false`，
这条断言就**无法区分「确实不支持」与「没测出来」**——正是 ADR-0007 反复要避免的假绿。

做法：用 `catch_unwind` **真去调用** shadow 相关 API，让 panic 成为**正面证据**。

| 观察项 | 结果 |
|---|---|
| L1–L5 连续投影 | **稳定等式**（每层的读数与上一层的输入严格一致） |
| `attachShadow` | **`todo!()`** ⇒ 稳定 panic（**不是编译失败**） |
| C9 判定 | **稳定 `false`** |

## 关键发现

### 1. 动态 DOM 与样式失效**成立**（L1–L5 稳定等式）

连续五层变更—重算—读数构成**稳定等式**，即每层的观测值都能由上一层的输入推出，
没有观察到状态漂移。**动态 DOM 与样式失效这两项是通过的。**

### 2. Shadow DOM 是 **`todo!()`**，panic 而非编译失败

`blitz-dom-0.3.0-beta.2/src/stylo.rs` 原文：

```rust
fn host(&self) -> <Self::ConcreteNode as TNode>::ConcreteElement {
    todo!("Shadow roots not implemented")        // :231
}

fn style_data<'b>(&self) -> Option<&'b style::stylist::CascadeData> {
    todo!("Shadow roots not implemented")        // :238
}
```

```rust
fn as_shadow_root(&self) -> Option<Self::ConcreteShadowRoot> {
    // TODO: implement shadow DOM
    None                                           // :311-313
}
```

另有 `:337` `parent_node_is_shadow_root` 恒 `false`、`:341` `containing_shadow_host` 恒 `None`。

**「panic 而非编译失败」这一点很重要**：它说明缺失发生在**运行时路径**上，
不是 API 不存在。所以探针若写成「API 不存在就跳过」就会漏掉它——
**必须真去调用**才拿得到这条证据。

### 3. 上游有一条**结构性限制**，不是「还没来得及实现」

`src/stylo.rs:319-327` 注释原文：

> This correctly uses a unique id for the `OpaqueElement` … However, it makes it
> impossible for us to "rehydrate" the `OpaqueElement` back into an actual Element
> which is **required to implement the `implicit_scope_for_sheet_in_shadow_root`
> method** … This is required to enable and use the Shadow DOM functionality in Stylo.

即：**即便把上面两个 `todo!()` 补上，Stylo 侧的
`OpaqueElement` 无法 rehydrate 这一问题仍会挡住 Shadow DOM。**
⇒ Shadow DOM 在 `blitz-dom 0.3.0-beta.2` 上**不是「补几个函数」能解决的**。

## 结论与裁决

> ### `DECISION = SWITCH_TO_STYLO`

**依据**：`SHADOW_DOM_WORKS = false`（稳定实测）⇒ 按 C11 判据，**T2.4 不通过**
⇒ 技术方案 §8 授权的替代路线**被触发**：切换为**直接 Stylo + Taffy + Parley**。

**这个裁决不是「探针失败」。** 判据是二值的：`SHADOW_DOM_WORKS` 为 `false` 即触发切换。
C1/C6/C7/C8/C10 为 true 说明**动态 DOM 与样式失效这两块能力是可以复用的**，
但**不能整体依赖 blitz 的 DOM 抽象层**。

## 对架构的直接影响（必须遵守）

1. **`layout-backend` 的对外接口不变。** 技术方案 §8 原文要求「业务接口保持不变」——
   **切路线只换 `layout-backend` 的内部实现，不动任何上层 crate 的边界**。
2. **必须自建的能力清单（C13，技术方案 §8 原文列举）**：
   DOM → 样式树 → box/fragment tree 的转换、匿名盒、inline formatting、字体回退、
   滚动、绝对/固定定位、transform、hit testing、table/float/writing-mode/复杂分页、
   SVG 几何、替换元素、表单控件。
3. **⚠️ 一条极易误判的事实，必须写进立项文件**：
   **切「直连 Stylo 路线」省掉的是 blitz 的 DOM 抽象层，不是样式与布局依赖。**
   已核实的依赖树含 `stylo 0.20` / `stylo_taffy` / `taffy 0.14` / `parley 0.11`
   （另有 `skrifa 0.44` / `fontique 0.11` 等字体栈）——
   **这些在直连路线下仍然要引入**。不写清楚会让人误以为切换能省掉整棵依赖树，
   从而低估工作量。**这正是技术方案 §8 所说的「不以『已有轮子』掩盖成本」。**
4. **成本依据须量化（C15）**：可量化项为「新增 crate 数 / 需自建的布局环节数 /
   需重跑的 PoC 数」。不接受「感觉更麻烦」这类不可比的说法。

## 附带的实测 API 约束（写代码时会踩）

| 约束 | 说明 |
|---|---|
| `Document` 是 **trait**，不是 struct | `pub trait Document`（`src/document.rs:130`）。直接 `Document::new()` 编不过，报 `E0782: expected a type, found a trait` |
| `blitz-traits` 无 `[features]` 段 | 写 `default-features = false` 无意义 |
| 触发重算用 `resolve` | `BaseDocument::resolve(&mut self, current_time_for_animations: f64)`（`src/resolve.rs:39`），注释原文「Restyle the tree and then relayout it」 |
| 变更 DOM 走 `mutate()` | `doc.mutate()` → `DocumentMutator`，有 `create_element` / `append_children` / `set_attribute` / `set_style_property` / `remove_node` 等 20+ 方法 |
| **不要设 `html_parser_provider`** | 本探针用 `DocumentMutator` 直接建 DOM，该字段是 `Option`，保持 `None` |

## 机器可验证

探针覆盖 C1（Linux 可用性，远程复跑）/ C2（无 GUI 依赖，grep `Cargo.lock`）/
C6（动态 DOM）/ C7（样式与布局两级失效）/ C8（NodeId 稳定）/ C9（Shadow DOM）/
C10（后端树只是缓存）/ C11（裁决行 `DECISION`）。

**注意语义区分**：`T2_4_PROBE_OK` 只表示「探针跑完且判定方法有效」；
`DECISION=SWITCH_TO_STYLO` 是**裁决结论**。**二者同时出现是合法且预期的组合**，
不是失败。

**判定方法自证**：C9 的证据是**主动 panic**（`not implemented: Shadow roots not implemented`），
而非「找不到 API」——这证明探针真的走到了那条路径。
若 C9 变成 `true`，说明是探针没调用到 shadow 路径（假绿），而非 blitz 支持了。

## 遗留与后续

1. **C4（html5ever 0.39 上重跑 T2.3 的 a~e 断言）在本轮不交付。**
   本地 cargo registry **只有 `html5ever-0.27.0`**，无 0.39/0.40（已核实），
   需联网 fetch；而 `blitz-html`（依赖 `html5ever ^0.39` 的那个）本地也无缓存。
   **本轮 T2.4 的验收依据不含 C4**——裁决由 C9 单独决定。
2. **若将来 blitz 新版实现了 shadow root 导致裁决翻转为 `KEEP_BLITZ`**，
   则 **C4 立即变成阻塞项**：必须先 fetch `html5ever 0.39` 再重跑 a~e，
   **不得默认沿用 ADR-0006 的结论**。
   （`markup5ever 0.12` → `0.39` 的 ADT 已是**源码级不兼容**，
   `TokenizerResult` 的位置与变体、`TreeSink` 的全套签名均变，
   ADR-0006 的五条结论**不能假定继承**。）
3. **本 ADR 的裁决只覆盖 T2.4 的三个问题**（动态 DOM / 样式失效 / Shadow DOM）。
   跨任务耦合项（html5ever 版本基线）归 T2.3-bis，不在本 ADR 范围。
