# ADR-0007：T2.1 结论 —— cppgc ↔ V8 跨语言环**无法**被回收，监听器引用必须单向

- 状态：**已接受**（PoC 实测，判定方法自证有效）
- 日期：2026-10-12
- 关联：`docs/TASKS.md` 的 T2.1
- 探针源码：`poc/t2_1_cppgc_cycle/src/main.rs`
- 运行方式：`cd poc/t2_1_cppgc_cycle && cargo run`

## 问题

技术方案 T2.1 要回答：`rusty_v8` / `cppgc` 能否回收**跨语言循环**
（`DOM → 监听器 → 闭包 → DOM`）。

## 实测结果（原文）

```
=== EXP1 基线：DOM 失去外部可达 ===
  WeakRef 判定：exp1 存活 = false（false = 已被 GC 回收）
=== EXP2 单向：DOM 强引用 JS 闭包（闭包不捕获 DOM）===
  WeakRef 判定：exp2 存活 = false（false = 已被 GC 回收）
=== EXP3 真循环：DOM → Global(闭包) → 闭包捕获 DOM ===
  WeakRef 判定：exp3 存活 = true（**true = 被跨语言环保活，即泄漏**）

=== 汇总（以 WeakRef 为准）===
  exp1: alive=false
  exp2: alive=false
  exp3: alive=true
BASELINE_VALID=true
CYCLE_LEAK=true
```

## 判定方法（这一段比结论更重要）

**不能用 `Drop` 判定「已回收」。** 第一版探针用 `impl Drop for DomNode` 打印作证据，
三个实验全部「成功回收」，但 `DROP_DOM` 输出全部出现在 `T2_1_PROBE_DONE` **之后**——
那是进程退出时堆销毁的统一析构，不是 GC。据此得出的「跨语言环也能回收」是假结论。

**也不能用 `Weak::with_finalizer`。** v8 crate 自己的文档注释写明该回调
「no guarantee as to *when* or even *if* the finalization callback will be invoked」。

**采用的方法：V8 内建 `WeakRef` + 独立 `HandleScope`。** 两条都是必需的：

1. 每个实验跑在自己的 `HandleScope` 里并在块结束时销毁——V8 把 HandleScope 内的
   `Local` handle 也当作 GC 根，只删全局属性不足以让对象不可达。
   漏掉这一步时，连 EXP1 基线都会误报「存活」，方法本身失效。
2. GC 后读 `weakRef.deref() !== undefined`，返回布尔量，确定性且无时序问题。

方法自证：`BASELINE_VALID=true` —— 基线（EXP1）确实被回收，说明判定不是恒真。

## 结论

**用 `v8::Global`（持久强引用）在 DOM 侧保存监听器闭包，会形成
`DOM → Global(闭包) → 闭包变量捕获 DOM` 的跨语言环，V8 GC 无法回收它。**

根因：cppgc 堆与 V8 堆是**两个独立堆**，V8 GC 只认识自己的根，而 `v8::Global`
正是这样一个根。于是闭包因 `Global` 存活 → 闭包捕获的 DOM wrapper 存活 →
cppgc 的 DOM 对象存活，全程没有任何一方判定它不可达。

EXP2 证明这不是「cppgc 不工作」：单向引用（DOM → 闭包，闭包不捕获 DOM）
能被正常回收。

### 对架构的直接影响（必须遵守）

1. **监听器在 DOM 侧只能存弱引用。** 用 `v8::Weak` 而不是 `v8::Global`；
   或采用「只向上」的单向设计：闭包持有宿主侧 `NodeId`（整数），
   回调时反查 DOM，DOM 侧不存 JS 句柄。
2. **若确实需要双向强引用**，必须实现跨堆追踪（ephemeron）——
   而 `v8` crate **未暴露** `TracedReference`（对 `src/` 全量 grep 无匹配），
   `Visitor::trace` 只接受 cppgc 自身的 `Traced`：

   ```rust
   // v8-152.2.0/src/cppgc.rs:157-166 原文
   pub struct Visitor(Opaque);
   impl Visitor {
       /// Trace a managed object.
       #[inline(always)]
       pub fn trace(&mut self, member: &impl Traced) { member.trace(self); }
   }
   ```

   即：**跨堆追踪只能在 `engine-v8` 内自行 unsafe 桥接到 V8 C++ 侧**，
   属铁律 6 高风险路径，须走决策上报并逐块 `SAFETY` 注释。
   **本轮 PoC 不做该桥接**，推荐直接选上面的弱引用/单向路线，成本与风险低得多。

## 附带的实测 API 约束（写 `engine-v8` 时会踩）

| 约束 | 说明 |
|---|---|
| `v8::V8::set_flags_from_string("--expose-gc")` | 缺此 flag 时 `request_garbage_collection_for_testing` 直接 FATAL |
| cppgc 堆**与 Isolate 绑定** | `CreateParams::default().cpp_heap(heap)`，不是全局单例 |
| Local handle 是 GC 根 | 判定回收必须销毁 HandleScope |
| `v8::String::new` 返回 `Option` | 直接 `.into()` 变不出 `Local<Value>`，需先 `.unwrap()` |
| `Function::new` 要 `&mut PinScope` | 其余多数 API 只要 `&PinScope`；scope 须绑 `mut` 后 reborrow |
| 宿主回调不返回 `Result` | 直接设返回值参数 `rv` |
| v8 scope 类型多生命周期参数 | 抽成具名函数会 E0106；用宏在同作用域展开 |

## 遗留（登记为 G1 前置）

- 「DOM 侧监听器槽」的具体类型（`Weak` vs `NodeId` 反查）随 `web-events` 的
  事件监听器模型一并决定，届时落对应 ADR。
- 若后续确需跨堆追踪，另起 PoC 验证 `TracedReference` 的 unsafe 桥接可行性。
